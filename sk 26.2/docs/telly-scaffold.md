# Scaffold — только Telly

В Scaffold удалены старый edge-mode, Jump Assist и переключатель Telly Mode.
Включение Scaffold теперь сразу включает Telly. Отдельный Coach и recorder сохранены
для ручных тренировок/записей; для автоматического Scaffold Coach нужно выключить.

## Запуск

Одиночный мир или сервер с разрешённой автоматизацией, клиентский timer 1x,
обычный tick rate 20, без creative flight и других gameplay-модулей. В одиночном
мире при необходимости `/tick rate 20`; на сервере модуль скорость не меняет.
На полной платформе повернуться вдоль X или Z и удерживать W или S.
Scaffold разгоняется, запрашивает прыжок у края, доводит видимую камеру к доступной
грани, ставит блоки на фиксированной высоте в одном ряду и возвращает взгляд вперёд.
RMB/Alt не нужны. При Auto Jump OFF прыгать Space вручную.

При открытии GUI/потере фокуса/отпускании W/S цикл сбрасывается. После возвращения
на полную платформу с W или S можно начать снова **без выключения/включения** модуля.
Причины паузы выводятся в чат при включённом Diagnostics. Если конфликтует другой
модуль, сообщение содержит его имя. После падения новый старт только с земли.
Остановка ввода не обнуляет инерцию: проверять над безопасной площадкой!

## Собственные настройки

| Настройка | Default | Назначение |
| --- | --- | --- |
| Telly Auto Jump | ON | Автоматический прыжок перед краем; OFF — ручной Space |
| Telly Sprint | ON | Sprint во время подхода/отрыва. При S сначала разворот по движению, затем реальный forward sprint, а не backward sprint |
| Telly Auto Switch | ON | Выбрать полный строительный блок из hotbar для клика, вернуть исходный слот |
| Telly Swing | ON | Взмах при принятом взаимодействии |
| Telly Diagnostics | ON | Сообщения о причинах паузы/отказа |
| Telly Jump Distance | 0.30 | Проверка отсутствия полного блока впереди, 0.10–0.80 блока |
| Telly Blocks | 3 | Верхняя граница новых блоков за прыжок, 1–4, не обязательная дальность |
| Telly Smart Stop | ON | Пересчитывать посадку по текущей скорости; укоротить серию и затормозить на достижимой части ряда |
| Telly Start Tick | 1 | Первый разрешённый воздушный тик, 0–8 |
| Telly CPS | 15 | Предел wall-clock попыток 1–15 CPS; небезопасные лучи пропускаются, burst после лага нет |
| Cam Lock | ON | ON: камера следует голове Scaffold; OFF: свободный обзор мышью |
| Telly Return To View | ON | Вернуть взгляд, сохранённый перед прыжком; OFF: направление подхода по выбранной оси X/Z |
| Telly Return Pitch | 20 | Pitch возврата при Return To View OFF, −60…80° |
| Telly Turn Speed | 180 | Скорость головы за 50 ms, 15–180°, применяется каждый кадр с учётом dt |
| Telly Return Speed | 180 | Скорость возврата головы за 50 ms, 15–180° |
| Telly Smoothing | 1 | 0.2–1, меньше — мягче и медленнее |
| Telly Reach | 4.5 | 2–4.5 блока, не выше native interaction range |
| Telly Aim Samples | 5 | 3–7 точек по оси грани |

Значения хранятся обычным ConfigManager. Старые параметры профилей не отображаются.
`.scafftrain start/stop/report/apply/undo` сохранены: apply переносит только скорости
в Telly Turn Speed и Telly Return Speed (с показом в report и ограничением диапазона),
но не sneak/release и не политику прыжков. Приоритет: Jump Turn Speed; иначе минимум
ground yaw/pitch. Assisted остаётся неприменимым. Undo возвращает предыдущие значения,
если после apply их не меняли вручную.

## Исправленные проблемы прежнего прототипа

- GUI, пустой слот и отпускание W больше не создают перманентный HALT.
- Удалён лишний переключатель Telly Mode, который по умолчанию оставлял старый Scaffold.
- Смещения 4/7/10 из замедленной записи больше не блокируют ранний допустимый клик.
  Настраиваются Start Tick и CPS; данные описывают движение, а не командуют им.
- После локального появления блока следующий target может обрабатываться в этом же
  callback, без отдельного пустого WAIT-тика.
- Цель подхода пересчитывается от текущей опоры: длинная платформа не оставляет старую
  далёкую цель. Прыжок по умолчанию начинается ближе к краю (0.30 вместо 0.85).
- Наведение/установка выполняются из renderFrame, независимо от 20 TPS input-цикла.
  После поворота в том же кадре выполняется новый raycast и при допустимом попадании
  native useItemOn; пакет передаёт фактическую позицию и ориентацию головы.
- W/S выбирают направление вдоль ближайшей оси X/Z (S — противоположное взгляду).
  RUN сначала разворачивает голову вдоль мирового движения, удерживая ввод до
  выравнивания yaw <5°. Затем подаёт forward input/sprint и запрашивает прыжок у
  края. В воздухе BUILD поворачивается к опоре. Это исправляет медленный S-цикл:
  он больше не пытается разгоняться обычным задним ходом. Для разгона всё равно
  нужна платформа, а не старт вплотную к краю. Скорость напрямую не подменяется.
- На старте запоминаются rowX/Y/Z и горизонтальное направление. Для X фиксируются
  Y/Z, для Z — Y/X. Разрешены только горизонтальные грани вдоль движения;
  UP/DOWN и боковое расширение ряда отвергаются.
- Приоритет — центр боковой грани. Если центр закрыт, поиск внутри центральной
  области 0.25–0.75; фактическое попадание вне области 0.2–0.8 не кликается.
- Возврат начинается после лимита блоков либо приземления. В Return To View сохраняется
  yaw/pitch перед прыжком; при OFF используется подход по X/Z, учитывая W/S.
- Cam Lock OFF: mouse/camera hooks отделяют обзор от фактической ориентации игрока.
  Голова и native raycast смотрят на опору, камера свободно управляется мышью.
  При выключении/паузе восстанавливается свободный взгляд только текущему игроку;
  при смене мира старые углы в нового игрока не записываются.
- Null/world/player/focus/finite guards и очистка цикла при отключении сохранены.

## Smart Stop

`TellyLandingPlan` каждый input tick прогнозирует пересечение ногами высоты
платформы из текущих x/y/z и vx/vy/vz: до 40 шагов, приблизительные gravity 0.08,
vertical drag 0.98, horizontal drag 0.91 и forward air control 0.02.
Это короткий прогноз без симуляции столкновений, эффектов и сетевых откатов.
Его результат переводится в количество непрерывных клеток от первого пробела
до предполагаемой посадки и ограничивается сверху Telly Blocks.

Например, максимум 4, фактическое движение даёт посадку на второй новой клетке:
модуль не обязан тянуться к четвёртой. После покрытия достижимой части на снижении
начинает возврат, убирает движение/sprint, подаёт sneak, а после посадки остаётся
в STOP. Отпусти W/S, затем нажми снова для нового цикла. Полный прыжок до лимита
может продолжать циклы автоматически. Smart Stop OFF оставляет фиксированный
максимум и не включает эту короткую остановку.

Прогноз обновляется и в RETURN: снижение скорости после ранних установок тоже
может включить торможение. Скорость и позиция не обнуляются искусственно, NoFall
нет: инерция, препятствия, эффекты, нехватка блоков и лаг способны сорвать посадку.
Smart Stop — помощь, а не гарантия, что игрок не упадёт.

## Серверы и ограничения

Scaffold больше не требует integrated singleplayer server. Native useItemOn,
reach/raycast, лимит CPS, finite/world/player guards и локальное ожидание блока
сохранены. Coach и Recorder остаются одиночными: это отдельная система тренировок.
Обход античита/защиты сервера не реализован. Проверять только на своём сервере или
там, где такая автоматизация разрешена. Отображаемый клиентский tick rate не
доказывает фактические TPS удалённого сервера.

Локальная prediction не является server acknowledgement: сервер может отклонить
установку, вернуть слот или позицию. При заметном скачке позиции цикл сбрасывается;
небольшая коррекция/задержка не всегда распознаётся. Первую проверку делать над
площадкой. Серверная совместимость/задержки/античит здесь не протестированы.

`tools/analyze_telly_episodes.py` нашёл в четырёх JSONL 27 кандидатов с 3+ разными
блоками на одной высоте, в прямом ряду: `docs/telly-episode-analysis.json`.
Это не обученная нейросеть. Настройки и прогноз — инженерный baseline.

Каждый клик требует свежего raycast, допустимой цели, полного опорного блока и
BlockItem. Приоритет — центр горизонтальной грани; верхние/нижние грани запрещены.
Нет tower/диагональных рядов/установки вне reach. 15 CPS — предел попыток, а не
гарантия 15 блоков/с. FPS, геометрия и native-правила уменьшают частоту.

Добавлены Java-регрессии X/Z и W/S, выравнивания для sprint, фиксированной высоты,
короткой посадки, обеих отрицательных осей и влияния скорости/торможения на прогноз.
В среде агента нет Java/Javac: компиляция и Java-тесты/игровой smoke test не выполнены.
Синтаксическая проверка не подтверждает API и физику Minecraft.

Проверить: +X/−X/+Z/−Z на W и S; достаточно места для разгона; Smart Stop с Blocks 4
и коротким прыжком; Smart Stop OFF; полный цикл; отпускание W/S после STOP; Cam Lock
ON/OFF и F5; GUI/focus/respawn/world; пустой слот и восстановление hotbar; private
server и локальные откаты. Тестировать над площадкой.

## Рекомендуемая отправная точка (не доказанный оптимум)

Auto Jump/Sprint/Auto Switch/Smart Stop/Diagnostics/Swing = ON; Blocks = 3;
Jump Distance = 0.30; Start Tick = 1; CPS = 15; Turn/Return Speed = 180;
Smoothing = 1; Reach = 4.5; Aim Samples = 5; Return To View = ON;
Return Pitch = 20 (не используется при Return To View ON); Cam Lock = ON для
проверки движений головы, OFF для комфортного свободного обзора.

Начинать на ровной платформе с 2–3 блоками запаса для разгона. Blocks 4 не создаёт
недостающую скорость: Smart Stop должен укорачивать недостаточный прыжок. Сохранённый
конфиг может оставить старые скорости 90: выставить 180 вручную. Высокий ping не
лечится увеличением CPS или Reach.

Источники: собственные JSONL и текущие Input/raycast/useItemOn hooks проекта.
Ранее проверена документация https://docs.fabricmc.net/26.2/develop/key-mappings.
YouGame https://yougame.biz/threads/117562/ не дал подходящего современного
лицензированного Telly-кода; чужой код не переносился. Зависимостей клиента не добавлено.
