# Scaffold training — запись и калибровка с подтверждением

Это статистический помощник, **не нейросеть** и не replay ручной траектории.
Он не обучает классификатор, не обещает обход античита и не гарантирует, что сервер
будет считать автоматизацию человеческим вводом. Объём кода сам по себе не повышает
качество модели: сейчас реализован проверяемый сбор данных и ограниченный baseline.

## Начало

Все `.scafftrain` — локальные клиентские команды, prefix по умолчанию `.`.
При другом prefix используй его. `/tick ...` — отдельная vanilla-команда одиночного
мира, требующая разрешения команд. Модуль сам не меняет TPS.

1. Открой одиночный мир, желательно отдельный тестовый мир над безопасной площадкой.
2. Выключи Scaffold и остальные gameplay-модули (Combat / Movement / Player и
   модули с affectsGameplay()). Запись не выключает их без разрешения: выдаст ошибку.
3. Обычные графические настройки и mouse sensitivity оставь такими, как будешь играть.
4. Выполни в игровом чате:

```text
/tick rate 3
.scafftrain start slow
```

5. Строй вручную 10–15 минут: вперёд, назад, боком, подход к краю, sneak, отпускание
   sneak, поворот и возврат. Не включай Scaffold. Можно добавить несколько прыжков.
6. Останови запись и дождись сообщения Saved:

```text
.scafftrain stop
.scafftrain report
```

Slow-запись сохраняется для изучения сырого движения, но **профиль из неё не
применяется и тайминги не умножаются на 20/3**. Камера, ввод, рендер и игровые тики
могут идти с разными скоростями. Затем нужна самостоятельная контрольная запись:

```text
/tick rate 20
.scafftrain start normal
```

Строй привычно 2–3 минуты. Нужны хотя бы 30 локально наблюдаемых установок моста,
30 секунд записи и не меньше 20 ground yaw + 20 ground pitch сэмплов движения
около установок. Для Jump Turn Speed нужны дополнительно 20 воздушных сэмплов
вращения около воздушных установок. Чисто прыжковая запись не заменяет наземную.
Обычный статичный мост без движения камеры может не дать достаточно данных.

```text
.scafftrain stop
.scafftrain report
```

Команда stop сохраняет и анализирует в фоне. Если ещё Saving — дождись завершения.
Report показывает предложенные настройки и предупреждения. Только после просмотра:

```text
.scafftrain apply
```

Apply требует выключенного Scaffold, валидного normal-профиля и предварительного
report. Scaffold и Jump Assist **не включаются автоматически**. Числовые настройки
сохраняются обычным ConfigManager. Чтобы отменить последнее применение в текущем
запуске клиента:

```text
.scafftrain undo
```

Undo не затирает настройки, изменённые вручную после apply: при несовпадении
откажется от всей операции. После перезапуска клиентский backup для undo исчезает.
Повторный apply после просмотра отчёта создаёт новый backup текущих значений.

Состояние записи:

```text
.scafftrain status
```

## Что действительно подбирается

Из нормальной записи отдельно считаются скорости yaw/pitch около установок,
повороты после установки, длительность sneak до установки, момент отпускания
sneak и воздушные повороты. Используются 85-й процентиль для скоростей и медиана
для измеренных задержек. Значения округляются и ограничиваются существующими
диапазонами NumberSetting.

Поддерживаемые предложения:

- Turn Speed;
- Pitch Speed;
- Return Speed (при достаточном числе post-placement yaw-сэмплов);
- Sneak Delay (при достаточном числе измеренных приседаний);
- Release Delay (при достаточном числе отпусканий);
- Jump Turn Speed (только при достаточной воздушной выборке).

Это приближения к текущим контролам, а не восстановление намерений: например,
вращение после установки не обязательно является возвратом камеры. Неизмеренные
параметры не придумываются: smoothing, multipoint, edge distance, reach, Place Delay,
jump prediction и логика выбора цели остаются прежними. Скорости вычисляются в
градусах за обычные 50 ms реального времени только для normal-профиля. Интервалы
слишком короткие, длиннее 250 ms и явные скачки позиции пропускаются.

Slow и normal — отдельные датасеты. Slow не смешивается с normal при вычислении
профиля. Сейчас нет автоматического сравнения paired-сессий, обучения между
запусками и загрузки произвольных JSON-профилей. Последний отчёт для report/apply
хранится в памяти текущего клиента; JSON-отчёт и сырые данные сохраняются на диске.
Новая запись очищает pending-профиль, но не удаляет предыдущие файлы.

## Данные и безопасность

В игровом working directory создаётся `skycore/scaffold-training/`.
При обычном Gradle runClient это `sk 26.2/run/skycore/scaffold-training/`.
На каждую запись — новый UUID и файлы:

- `<uuid>.jsonl` — session header, строки sample/tick/use, end footer;
- `<uuid>-report.json` — статистика, причины отказа, предложенные настройки.

Записываются относительное monotonic-время в ns, clientTick, worldTick,
объявленный tickrate, номер непрерывного segment, координаты, yaw/pitch, grounded,
WASD/jump/sneak/sprint,
hotbar slot / main-hand item, target/face/hit, использованная рука/предмет,
yaw/pitch в момент взаимодействия и локальный исход BlockItem use.
Строка use записывает также неудачные попытки; только consumed + изменение
заменяемой цели на полный блок под/около ног попадает в bridge-статистику.
Это геометрическая эвристика: не ручная разметка и не подтверждение сервера.

Пароли, chat, имена игроков, адрес сервера, название мира и seed не записываются.
Загрузки на сервер, облачного обучения и внешних запросов в recorder нет.
Координаты всё равно являются локальными данными — проверь файл перед передачей.
Имена файлов не задаются командами; существующие symlink-пути отвергаются.
Существующие датасеты не перезаписываются (CREATE_NEW).

Лимиты: 20 минут реального времени, 60 000 camera samples, 10 000 use observations,
до 40 samples/second и очередь записи на 4096 строк. Письмо на диск и анализ идут
в выделенном потоке. При переполнении запись останавливается, профиль неприменим.
При ошибке I/O выводится сообщение и лог, неполный файл сохраняется. У полного
датасета есть end footer; аварийное закрытие процесса может оставить partial-файл.
При штатном закрытии клиента writer ожидается до 5 секунд.

Смена мира/объекта игрока останавливает запись. Смена TPS, включение gameplay-модуля
или автоматического rotation-controller завершает её с ошибкой и блокирует apply.
GUI/пауза, frozen-world, смерть, spectator, транспорт и полёт исключаются из
сэмплирования. Возврат начинает новый segment: даже короткая пауза не
считается одним непрерывным поворотом. Replay,
расширенные обработчики телепортаций/лагов и распознавание других модификаторов
ввода не реализованы — запись должна быть действительно ручной.

## Проверки

Добавлена `testScaffoldTraining` (подключена к check): pure Java-тесты анализа без
Minecraft, покрывающие yaw wrap, процентили, пустую/достаточную/slow/mixed-TPS
выборку, ошибочную сессию, неподтверждённый consumed action и разделение air/ground.

В среде агента нет Java/Javac: компиляция и тест не запускались. Синтаксис проверяется
Java tree-sitter; это не проверка сигнатур Minecraft API. Нужна ручная проверка:

1. Отказ start в multiplayer и при активном Scaffold/Sprint и т.п.
2. Slow на 3 TPS: stop сохраняет файлы, apply отказывается даже после report.
3. Normal на 20 TPS с достаточными данными: report → apply, Scaffold остаётся OFF;
   undo возвращает значения; ручная правка после apply блокирует undo.
4. Apply до report / во время записи / при активном Scaffold отказывается.
5. Пауза, F1, GUI, смена мира, tick freeze, смена TPS, включение модуля:
   без фоновых установок, stale world/player и применимого загрязнённого профиля.
6. Завершение/повторный start при Saving, read-only папка, ошибка диска/очереди,
   штатное закрытие клиента: ошибка видима, прежние файлы не перезаписаны.
7. Проверить осмысленность предложений на отдельном безопасном мосте перед
   использованием: статистический baseline может потребовать ручной коррекции.

## Источники

Самостоятельная реализация на существующих EventBus, PlayerInputEvent,
ClientTickEvent, ClientRenderEvent, ClientCommand, useItemOn-mixin, NumberSetting
и ConfigManager. Новых runtime-зависимостей нет. Код других клиентов не переносился.

- Поиск YouGame: https://yougame.biz/tags/rotation/ — обсуждения записи сэмплов,
  но подходящего проверенного примера для 26.2 не найдено; код не заимствован.
- https://github.com/FabricMC/fabric-api/issues/5623 — упоминание
  Minecraft.getSingleplayerServer() для Fabric 26.2 / JDK 25. Никакие операции
  остановки integrated server из обсуждения не используются.
- https://mappings.dev/1.21.11/net/minecraft/world/TickRateManager.html — справка
  tickrate()/isFrozen() для прежней версии; не доказательство сборки на 26.2.
  Для нового обращения к tickRateManager необходима фактическая компиляция.
