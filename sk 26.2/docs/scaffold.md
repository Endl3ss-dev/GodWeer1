# Scaffold — edge / sneak / visible aim

Модуль Movement для обычных полноразмерных блоков. Это помощник строительства,
а не гарантия безопасности, незаметности или совместимости с античитом.

## Цикл

1. В PlayerInputEvent рассчитывается мировое направление WASD относительно yaw.
   Короткий collision probe ищет отсутствие земли под проекцией центра игрока.
   Учитываются Edge Distance и текущая горизонтальная скорость (общий предел 0.55).
2. У края включается sneak и убирается sprint. Клавиши KeyMapping не меняются:
   модуль меняет только текущий Input. Физически удерживаемый Shift не отпускается.
3. Пока боковая грань ещё не видна, игрок медленно подходит в vanilla sneak.
   Без подходящих блоков движение приостанавливается сразу. Задержки и поворот
   не выключают приседание. Встроенное поведение vanilla sneak ограничивает шаг
   за край; отдельного телепорта или принудительной коррекции velocity нет.
4. Как только найдена видимая опора, фиксируется цель и сохраняется исходный взгляд.
   Ввод движения и прыжка временно блокируется, камера явно поворачивается к грани.
   Это позволяет удерживать W при строительстве вперёд, не разворачивая само движение
   вместе с камерой. Остаточный импульс не обнуляется.
5. Установка разрешена только после sneak-задержки, достижения углов и фактического
   raycast в ту же грань того же блока, без препятствий и пересечения цели игроком.
   Между достижением угла и кликом всегда проходит хотя бы один vanilla tick,
   чтобы обычное movement-обновление успело передать взгляд без поддельных пакетов.
6. Временно выбирается блок, вызывается vanilla useItemOn, затем исходный слот
   восстанавливается в finally с серверной синхронизацией через InventoryHelper.
7. Модуль ждёт непустую цель в клиентском мире, выдерживает Release Delay,
   возвращает камеру и отпускает собственный sneak/блокировку движения. Если впереди
   опять пусто, следующий цикл начинается автоматически. Пустая цель после таймаута
   или отклонённое взаимодействие приводят к возврату взгляда и задержке повторения.

Важно: клиентский мир содержит prediction. Наблюдение блока не является отдельным
server acknowledgement. При откате сервером край проверяется заново; абсолютной
защиты от падения при лаге, большой скорости или внешнем толчке нет.

## Настройки

Все настройки сохраняются обычным ConfigManager. Скорости заданы на игровой tick,
а не на render frame, и не зависят от FPS.

| Настройка | По умолчанию | Диапазон / назначение |
| --- | --- | --- |
| Auto Switch | true | Поиск блоков в hotbar; иначе только выбранный слот |
| Swing | true | Взмах после принятого взаимодействия |
| Return View | true | Вернуть взгляд перед продолжением движения |
| Require Movement | true | Начинать цикл только при вводе движения |
| Edge Distance | 0.22 | 0.05–0.4 блока, запас обнаружения края |
| Turn Speed | 18 | 2–60 градусов yaw за tick |
| Pitch Speed | 12 | 2–45 градусов pitch за tick |
| Return Speed | 24 | 2–60 градусов за tick; видна при Return View |
| Sneak Delay | 2 | 1–10 ticks приседания перед установкой |
| Place Delay | 1 | 0–10, число aligned-ticks ожидания; минимум один полный tick даже при 0 |
| Release Delay | 2 | 0–10 дополнительных ticks после наблюдения блока |
| Retry Delay | 5 | 1–20 ticks до следующей попытки после сбоя; отсчитывается и при возврате |
| Cycle Timeout | 60 | 20–120 ticks отдельно на наведение / ожидание блока |
| Place Reach | 4.0 | 2–4.5 блока, ограничено также blockInteractionRange |

Выключение Return View оставляет камеру направленной на мост; дальнейшее WASD
относительно этого взгляда. Для сценария «удерживаю W и строю вперёд» оставлять
Return View включённым. На очень малых скоростях поворота нужно увеличить timeout.

## Проверки и отмена

- Нет установки в GUI, при атаке/ручном использовании, еде, смерти, spectator,
  транспорте, воде, лаве, полёте или отсутствии player/level/gameMode.
- Прыжок и потеря onGround отменяют цикл: jump намеренно возвращает управление
  игроку, а не удерживает его на платформе против его воли.
- Другие активные RotationManager / ServerRotationManager / RotationController
  и чужая camera entity отменяют цикл без перехвата их поворотов.
- Замена объекта player/world и смещение более 0.75 блока во время цикла
  сбрасывают старую цель (respawn, смена мира, teleport/knockback).
- Земля ищется через collision API, а не только по признаку air.
- Цель должна быть заменяемой, внутри world border и не ниже minY.
- Опора — полный collision block без жидкости; исключены EntityBlock,
  crafting table, respawn anchor, note block.
- Материалы — непустые BlockItem с полной collision shape, без FallingBlock
  и EntityBlock: песок, гравий, плиты, ступени и контейнеры не выбираются.
- Проверки цели, опоры, расстояния, текущего raycast и hotbar повторяются при установке.
  Коллизии с остальными entities и допустимость конкретного размещения проверяет vanilla.
- Один клик за цикл, без packet-spam и поиска сквозь стены. Есть timeout на ожидание
  и защита от бесконечного RETURN при ручном движении мыши (200 ticks).
- Отписка от событий при выключении; без принудительного отпускания физического Shift,
  изменения KeyMapping, оставленного выбранного слота или резкого возврата камеры.

Остановка из-за GUI/еды/прыжка/конфликта поворотов прекращает автоматическую защиту:
дальше управление остаётся у игрока. На диагональных разрывах без видимой соседней
опоры модуль может остановиться в sneak; он не ставит цепочки вспомогательных блоков.
Не предназначен для tower, лестничных/частичных поверхностей, паркура и speed-модулей.
Мышь не блокируется: ручное наведение может отложить клик или вызвать timeout.

## Проверки разработки

Добавлена Gradle-задача `testScaffold` в существующий headless sourceSet `auraTest`.
Она проверяет мировое направление WASD, нормализацию диагонали, переход yaw через
±180°, ограничение углового шага, сходимость, регистрацию настроек и их диапазоны.
Подключена к `check`. Это не симуляция world, raycast или сетевого обмена.

В текущей среде нет java/javac, поэтому Java-тест и сборка не запущены.
Синтаксис Java проверен tree-sitter; это не type-check и не проверка Minecraft API.
Инструмент проверки размещён только в игнорируемом `.gradle-user/scaffold-check`.

### Ручной тест в локальном мире (ещё не выполнен)

1. Над безопасной площадкой строить мост с stone, удерживая W: sneak у края,
   остановка, видимый поворот назад/вниз, клик, возврат, продолжение движения.
2. Повторить для S, A, D, диагоналей, исходного yaw около ±180°, включённого sprint.
   Убедиться, что поворот не меняет направление движения во время AIM/RETURN.
3. Проверить минимальные/максимальные задержки, скорости поворота и reach;
   медленное наведение с малым timeout должно корректно прерывать попытку.
4. Проверить ручной Shift, отпускание WASD, движение мышью, jump, RMB/LMB,
   инвентарь, еду, воду, элитры и выключение на каждом этапе. Нет залипшего ввода.
5. Проверить пустой hotbar, последний блок в стаке, Auto Switch off, непригодные
   материалы и отсутствие видимой опоры. Не должно быть холостого packet-spam.
6. Проверить препятствие между глазами и гранью, удаление опоры перед кликом,
   занятую цель, край world border, появление entity в месте установки.
7. На локальном сервере проверить отклонение/откат установки, большой ping,
   откат позиции и смену dimension/respawn во время AIM/WAIT/RETURN.
8. Включить конфликтующий модуль поворота: Scaffold должен уступить управление.
   Проверить сохранение настроек и отсутствие повторных подписок при enable/disable.

## Источники

Код написан самостоятельно под текущий SkyCore. Использованы PlayerInputEvent,
Subscription, Rotation.lookingAt, проверки менеджеров вращения и
InventoryHelper.selectHotbarSlot. Другие клиенты не копировались.

- YouGame: https://yougame.biz/threads/117562/ — поисковая выдача по Scaffold /
  eagle / sneak / raytrace. Подходящего современного примера реализации в выдаче
  не найдено, код и лицензии сторонних клиентов не заимствованы.
- https://docs.neoforged.net/primer/docs/26.2/ — прочитана начальная часть справки
  по vanilla API 26.2, в частности перенос screen в Minecraft.gui; не используется
  как Fabric API и не добавляет зависимость NeoForge. Конкретные вызовы input,
  collision, rotation и useItemOn сверены с исходниками текущего SkyCore.
