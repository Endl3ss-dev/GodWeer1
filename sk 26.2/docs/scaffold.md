# Scaffold — Eagle и Telly

`ScaffoldModule` работает в двух режимах: `Eagle` (по умолчанию) — защита от
падения с края и опциональная автоматическая установка блоков, и `Telly` —
мостовой scaffold.

Модуль слушает события `PlayerTickEndEvent` и `PlayerInputEvent`; подписки
открываются в `onEnable` и закрываются в `onDisable`.

## Настройки

| Настройка | Значение по умолчанию | Описание |
| --- | --- | --- |
| `Mode` | `Eagle` | Режим работы: `Eagle` или `Telly` |
| `AutoPlace` | `false` | Автоматически устанавливать блок; действует только в `Eagle` |
| `CPS` | `10` | Максимум автоматических установок в секунду, диапазон `1–20` |
| `AutoSwitch` | `Silent` | Способ выбора ячейки со строительным блоком |
| `Rotate` | `Normal` | Способ ротации к грани блока-опоры (`Eagle`) |
| `ClientLock` | `true` | Показывать управляемую ротацию на экране игрока |
| `SafeWalk` | `false` | Удерживать Shift на краю (`Telly`) |
| `AllowShift` | `false` | Разрешить установку при зажатом Shift (`Telly`) |
| `Legit` | `true` | Не ставить, пока хитбокс ещё касается опоры (`Telly`) |
| `Telly` | `false` | Ждать падения перед установкой; фиксировать высоту моста (`Telly`) |
| `KeepHeight` | `false` | Держать фиксированную высоту моста (`Telly`) |

Видимость настроек зависит от режима:

- `CPS`, `Rotate`, `ClientLock` — только при `AutoPlace = true` в режиме `Eagle`;
  `ClientLock` дополнительно скрывается при `Rotate = None`;
- `AutoSwitch` — при `AutoPlace = true` либо в режиме `Telly`;
- `SafeWalk`, `Legit`, `Telly`, `KeepHeight` — только в режиме `Telly`;
- `AllowShift` — в `Telly` и только при выключенном `SafeWalk`
  (при `SafeWalk` клавишей Shift управляет сам модуль).

### `AutoSwitch`

- `Normal` — выбрать строительный блок в hotbar обычным способом и оставить его выбранным;
- `Silent` — локально подменить выбранную ячейку на время установки и вернуть исходную;
- `Inventory` — временно обменять блок из основной inventory с текущей ячейкой
  (`ContainerInput.SWAP`) и вернуть содержимое обратно;
- `None` — не искать другую ячейку: используется только блок в руке.

Offhand проверяется первым: если в левой руке строительный блок, он и ставится.
Если в основной inventory блока нет, `Inventory` откатывается на hotbar-путь.

### `Rotate`

- `Normal` — мгновенная ротация через `RotationManager.updateExact`;
- `Smooth` — плавная ротация с ограничением скорости;
- `Linear` — фиксированный угловой шаг за клиентский тик;
- `None` — ротация не меняется; установка выполняется по текущему crosshair
  (`minecraft.hitResult`), то есть навести на грань нужно вручную.

### `ClientLock`

- `true` — управляемая ротация видна на экране игрока;
- `false` — silent-ротация через `RotationManager`: камера остаётся свободной
  (`FreeLookController`), строить можно, глядя вперёд.

## `Eagle`

При включённом `Eagle` модуль удерживает `options.keyShift`, если блок под
игроком — воздух (или игрок физически держит Shift). При отключении модуля
Shift отпускается, активная ротация прекращается.

### `AutoPlace`

Модуль ищет заменяемую клетку под игроком, находит видимую грань соседнего
твёрдого блока-опоры в пределах `blockInteractionRange`, проверяет её реальным
рейкастом и ставит блок. Интервал между установками ограничен `CPS`.

**Строительство по одной оси.** Пока игрок движется, мост строится только по
доминирующей оси движения (`X` или `Z`, с гистерезисом против переключений на
диагоналях):

- опора ищется только позади игрока вдоль этой оси, затем — блок под целью;
  боковые грани не используются;
- yaw фиксируется на кардинальном направлении против движения, от точки
  установки зависит только pitch;
- ввод движения пересчитывается через `MovementHelper.fixMovement` относительно
  управляемой ротации, поэтому разворот головы не меняет мировую траекторию.

Ось определяется по клавишам движения относительно направления взгляда
(при silent-ротации — free-look), а не по повёрнутой голове. Спринт при
управляемой ротации игнорируется.

Если игрок стоит на месте, используется свободный поиск лучшей видимой грани.

## `Telly`

Установка строится на настоящем рейкасте: для каждой клетки-кандидата и каждой
грани опоры выбирается точка прицеливания, поворот к ней квантуется по GCD
(`MouseSensitivity.getGCDValue`), вдоль этого поворота
(`Vec3.directionFromRotation`) кастуется луч, и в пакет установки уходит именно
точка попадания луча, а не синтетическая точка.

Последовательность одного тика:

1. гейты: прыжок при `Telly`, Shift (`SafeWalk` / `AllowShift`), наличие блока;
2. выбор клетки: `KeepHeight`/`Telly` держат зафиксированную высоту моста,
   иначе берётся клетка под игроком;
3. `SafeWalk` удерживает Shift, пока целевая клетка пуста;
4. `Legit` — не ставить, пока уменьшенный хитбокс ещё пересекает опору;
5. поиск плана: 14 смещений-кандидатов × 6 граней, проверка заменяемости
   клетки, свободности от игрока, твёрдости опоры и попадания луча в нужную
   грань в пределах `MAX_REACH` (4.5 блока);
6. установка: блок в руку → `sendPosRot` с углами прицеливания → `useItemOn` →
   возврат слота → `sendPosRot` с углами камеры.

### Порядок пакетов

`Telly` ставит блок «легально», но с явной отправкой углов: перед `useItemOn`
уходит `ServerboundMovePlayerPacket.PosRot` с углами прицеливания, после
установки — второй `PosRot` с углами камеры, чтобы сервер не сохранил
поворот установки.

**Важно:** это два позиционных пакета за тик. Серверные проверки движения
читают такую пару как телепорт и отвечают сетбеком (setback) — блок тогда
ставится туда, где игрока уже нет, и мост «теряет» блоки. Именно на этой схеме
был баг «ставит 2 блока и всё». Для `Eagle → AutoPlace` такая схема
не используется: там ротация уходит с обычным пакетом движения тика, а лишний
`PosRot` не отправляется.

## Зависший контейнер (InvSaver и похожие модули)

Модуль, который закрывает экран контейнера без пакета закрытия, оставляет
`player.containerMenu` указателем на чужое меню, хотя экран уже закрыт.
В этом состоянии `AutoSwitch → Inventory` отправил бы `handleContainerInput`
с `containerId` контейнера, которого игрок уже не видит.

Поэтому `Inventory`-своп выполняется только при
`player.containerMenu == player.inventoryMenu`. Если меню чужое,
`Inventory` откатывается на hotbar-путь, который не зависит от состояния
контейнера, и возвращает слот после установки.

## Совместимость

`ScaffoldModule.handlePacketDelay(Packet)` сохранён как no-op, возвращающий
`false`: его вызывает `ConnectionPrepareViaNativeConnectMixin`. Буферизация
пакетов (прежний `GrimBlockFly`) удалена, задержки пакетов больше нет.
