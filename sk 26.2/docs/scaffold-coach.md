# Scaffold Coach — локальный тренажёр flat Speed Telly

Отдельный модуль в Movement, выключен по умолчанию. Помогает отрабатывать цикл
«разгон → ручной прыжок → поворот назад → несколько установок → возврат взгляда»
на одном Y блоков. **Это тренажёр и размеченная запись, не готовый автоматический
Telly-контроллер и не нейросеть.** Три блока — цель упражнения, а не гарантия.

## Почему не `/tick rate 3`

Одиночный integrated server оставляется на 20 TPS. Существующий клиентский
ResetSpeedHelper / DeltaTracker замедляет только клиентскую симуляцию, по умолчанию
до 0.25x. Ввод камеры остаётся в реальном времени. Серверные мир/мобы/жидкости не
замедляются: это не идентичная vanilla slow motion и не эталон физики 20 TPS.

Обычный Minecraft.startUseItem привязан к клиентским тикам. Для Coach нажатие/удержание
RMB читается из реального ввода в renderFrame, пересчитывается актуальный raycast и
вызывается обычный gameMode.useItemOn. Перед взаимодействием отправляется реальная
позиция/реальный вид игрока (PosRot), чтобы сервер не ждал следующего медленного
movement tick. Поддельной точки взгляда и прямого setBlock нет. Дублирующий vanilla
startUseItem отменяется только для основного BlockItem в активном Coach-контексте.

Это убирает привязку dispatch к замедленному клиентскому tick, но **не обещает
мгновенного подтверждения сервера**: остаются native prediction, коллизии, проверки
reach и возможные откаты. Режим разрешён только в одиночном мире. Замедление клиентской
физики при сервере 20 TPS экспериментально: сначала проверь короткий прыжок над
безопасной площадкой, особенно столкновения, движение и приземление.

## Быстрый старт — команды в игровом чате

1. Открой тестовый одиночный мир, встань на полный твёрдый блок, выключи остальные
   gameplay-модули (включая Scaffold, Sprint, Timer). Не находись в creative flight.
2. Повернись по направлению будущего прямого моста (X или Z): эта строка будет
   зафиксирована. Верни серверу нормальную скорость и включи тренажёр:

```text
/tick rate 20
.scafftrain coach on
```

3. Закрой чат, отпусти RMB один раз после включения/возврата из GUI. По умолчанию:
   - **K** — выключить/включить клиентское замедление;
   - **удерживать Left Alt** — плавная доводка к ближайшей видимой точке;
   - **RMB** — ручная установка / повтор при удержании;
   - WASD, sprint, jump и возврат камеры контролируешь самостоятельно.
4. Начни короткую запись:

```text
.scafftrain start assisted
```

5. Выполни несколько разгонов и прыжков. Перед установками удерживай Alt, затем
   отпускай его и сам разворачивайся вперёд. Не жди автоматического выполнения
   трёх установок: держи/нажимай RMB, пока видна допустимая грань.
6. Останови, дождись Saved и посмотри отчёт:

```text
.scafftrain stop
.scafftrain report
```

7. Полностью выключить тренажёр:

```text
.scafftrain coach off
```

Дополнительные команды:

```text
.scafftrain coach slow
.scafftrain coach status
.scafftrain coach height
```

Height запоминает новую высоту полного блока под ногами только когда стоишь на
земле. То же действие есть в настройках как Reset Bridge Origin (запоминает также направление и строку X/Z). Другой prefix
вместо `.` используется обычным CommandManager.

## Настройки Scaffold Coach

| Настройка | Default | Назначение |
| --- | --- | --- |
| Practice Speed | 0.25x | 0.15–1.0, коэффициент клиентской симуляции |
| Slow Toggle Key | K | Мгновенное переключение, обработка вне медленного tick |
| Aim Hold Key | Left Alt | Помощь только пока клавиша удерживается |
| Coach Aim Speed | 180 deg/s | 30–540, реальное время, не количество render frames |
| Coach Aim Cone | 180° | 15–180; уменьшить, если нужна только небольшая доводка |
| Practice Click Delay | 150 ms | 80–500 реальных ms между попытками при удержании RMB |
| Coach Aim | true | Отключить доводку, оставив slow motion и обработку ручных кликов |
| Lock Bridge Line | true | Только прямая строка X или Z вперёд от стартовой платформы |
| Three Block Cue | true | Сообщение при третьем локально наблюдаемом блоке в прыжке |
| Reset Bridge Origin | action | Перезапомнить Y, направление и строку на твёрдой платформе |

Точка выбирается по минимальному углу от прицела среди видимых точек на гранях
соседних полных блоков. Геометрия/raycast общая со Scaffold. Поиск ограничен плоскостью
моста, областью ±3 блока X/Z и текущим blockInteractionRange, не выше 4.5 блока.
При Lock Bridge Line не выбираются боковые клетки или продолжение назад:
помощь не должна случайно расширять ряд вместо трёх последовательных блоков.
Нет наведения сквозь стены. Если нужная грань уже под прицелом, лишний разворот не нужен.
Между поисками (не чаще 20 раз/с) доводка идёт по реальному dt с верхним ограничением
шага кадра. Физические WASD/jump/sneak и velocity модуль не подменяет.

Y цели — всегда высота блока стартовой платформы. Прыжок меняет Y игрока, а не Y
строящегося ряда. Автоподъёма ряда, tower, автопрыжка, авторазгона, автоповорота
вперёд и автоматического счётчика «обязательно поставить ровно 3» нет. Сообщение
о трёх блоках учитывает только локальное изменение, не server acknowledgement.
Повторная попытка в той же клетке в одном прыжке не увеличивает счётчик.
Основная рука должна содержать полный BlockItem без FallingBlock/EntityBlock.
Автовыбора hotbar и работы с offhand в realtime-пути нет.

## Возврат скорости и восстановление

- K восстанавливает обычную скорость без ожидания клиентского tick.
- При падении ниже верхней поверхности моста более чем на 0.2 блока в воздухе
  замедление выключается автоматически. Вернись на платформу и нажми K заново.
- В GUI, паузе, при потере фокуса окна, смерти, жидкости, полёте и транспорте
  заимствованный timer освобождается; доводка и realtime-клики не выполняются.
- Смена мира/объекта player, multiplayer, TPS не 20, другой gameplay-модуль или
  активный rotation-controller выключают Coach полностью.
- При выключении/смене мира восстанавливается только принадлежащее Coach значение
  ResetSpeedHelper. Если другой владелец уже поменял timer, его значение не затирается.
- Возврат из GUI требует отпустить RMB, чтобы не было установки из старого удержания.
  Очередь native use-clicks дренируется только для заменяемого Coach-пути.

Если уже применён `/tick rate 3`, Coach откажется включаться. Сначала выполни
`/tick rate 20`: модуль специально не меняет и не забывает чужую скорость сервера.

## Запись и честность калибровки

Для тренажёра используй `start assisted`, а не `start normal`. Schema 2 записывает
фактический clientSpeed и assisted-маркер каждого sample; Frame содержит State
тренажёра: slow/aimApplied, фиксированный Y, направление/начало строки,
номер прыжка и число наблюдаемых блоков.
Метка assisted остаётся даже при временно выключенном K замедлении.

Отчёт дополнен измерениями последовательности: число завершённых прыжков,
среднее число уникальных целевых блоков за прыжок, прыжки с 3+ блоками, плоские ряды, доля одного Y,
средний разворот yaw, реальная длительность прыжка и число client ticks.
Пауза/GUI разрывают сегмент и не склеиваются в «успешный прыжок».

Эти измерения помогают исследовать желаемый рисунок Telly. Но assisted-сессия
**не применяется** как профиль человеческой ротации через apply: доводка и частота
кликов созданы помощником. Normal-запись требует выключенного Coach и таймера 1x.
Для полноценного обучения автоматического Telly нужна отдельная модель/политика
и проверка на новых данных; текущие процентили её не заменяют.

## Проверки

Добавлены тестовые случаи clock ownership, нулевого dt, маркировки assisted,
защиты от normal-метки на замедленных данных и синтетического flat-прыжка с тремя
установками. Java/Javac в среде агента нет: тесты и компиляция не выполнены.
Синтаксическая проверка не подтверждает Minecraft API или игровое поведение.

Ручной smoke test перед длинной записью:

1. Включить Coach на платформе при 20 TPS; проверить K и нормальный возврат скорости.
2. Jump → ручной разворот/Alt → RMB: актуальный raycast, нет установки без RMB,
   удержание Alt без RMB только доводит. Проверить короткие клики и удержание.
3. Убедиться, что один RMB не вызывает два useItemOn (Coach + vanilla), а после
   disable, GUI и потери фокуса нет отложенных лишних кликов.
4. Отпустить Alt и быстро отвернуться: новый клик не должен использовать старую грань.
5. Три плоских блока при прыжке: Y не растёт; блок не появляется вне reach/за стеной.
6. Упасть: скорость восстанавливается до длительного падения; полётом/обычным
   движением вернуться на платформу, K снова включает замедление.
7. GUI, F1, потеря фокуса, pause, respawn, TPS 3, Timer/Scaffold, смена мира:
   безопасное освобождение timer, запрет multiplayer и отсутствие залипания.
8. Assisted → stop → report: последовательности сохранены, apply отказан.
   Coach OFF → normal: чистая запись по-прежнему может дать профиль.

## Источники

Использованы существующие ResetSpeedHelper/DeltaTracker-mixin, KeyEvent/KeyBinds,
renderFrame/startUseItem hooks, PosRot-вызов из AimbotModule, useItemOn и геометрия
Scaffold. Код других клиентов не переносился, зависимостей не добавлено.

YouGame поиск по Telly/Scaffold не дал подходящего современного примера:
https://yougame.biz/threads/117562/ — только общее описание.
Справочный поиск по механике Telly:
https://www.sportskeeda.com/minecraft/minecraft-1-19-use-different-speed-bridge-methods
— использован как описание последовательности, не как источник API/кода.
Реализована именно запрошенная плоская тренировочная вариация; чужие определения
классического Speed Telly с подъёмом ряда не подменяют это требование.

Официальная документация Fabric для KeyMapping.consumeClick(), версия 26.2:
https://docs.fabricmc.net/26.2/develop/key-mappings — прочитана; не заменяет
компиляцию и проверку realtime-пути непосредственно в игре.
