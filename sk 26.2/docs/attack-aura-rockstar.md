# Attack Aura: ротации Rockstar и коррекция V2

В `Attack Aura → Режим ротации` к четырём прежним вариантам добавлены десять с префиксом **Rockstar**. Старые `ReallyWorld`, `HvH`, `Funtime`, `HolyWorldLegit` остаются отдельными режимами; по умолчанию по-прежнему выбран `ReallyWorld`. Например, переключить старый профиль на вариант донора можно, только явно выбрав **Rockstar ReallyWorld**.

| После префикса Rockstar | Как ведёт себя наводка |
|---|---|
| Простой | Ближайшая точка хитбокса; при расстоянии между глазами более трёх блоков горизонтальный угол берётся по центру цели. |
| HolyWorld | Видимый поворот камеры каждый **кадр**: интерполяция и сглаживание центра цели, более мягкий pitch, учёт ручного движения мыши и накопление дробного шага чувствительности. `Client Look` не требуется. Это не `HolyWorldLegit`. |
| VonTam, FunTime | Два пункта для **одного** алгоритма, как у донора. Когда удар готов, учитывается горизонтальное движение игрока за один тик, а амплитуда волн по двум осям уменьшается в четыре раза. |
| SpookyTime | Учитывает движение игрока за два тика, добавляет небольшой угловой разброс и медленнее меняет pitch по падающей цели. |
| OneTick | Сохраняет угол для конкретной цели, пока луч продолжает попадать; пересчитывает при промахе или смене цели. |
| ReallyWorld | Поворот к ближайшей точке, ограничение шага 160° по каждой оси. Использован обычный путь донора, не ветка для старых протоколов. |
| SlimeWorld | Волновые смещения, отдельная реакция на невидимую точку глаз, планирование цели и блок у её ног. Pitch ограничен ±85°. |
| Sloth | Точки в верхней половине хитбокса, плавная смена смещений каждые пять тиков. При готовности удара скорость поворота выше. |
| Без поворота | Aura не ставит задачу ротации и не меняет ввод. Атаки остаются под обычными проверками профиля, дистанции, таймера и луча. |

Кроме `HolyWorld`, активные режимы делают шаг на физическом тике, а не на каждом опросе таймера атак. Режимы кликов `1.8` и `1.12`, пауза после клика и визуальное дрожание работают [как раньше](attack-aura-clicks.md). В полёте с включённым `ElytraTarget` сохраняется его штатное предсказание; `Без поворота` не наводит Aura и в полёте. Для разрешённых профилем BedWars снарядов вместо точек живой модели используется центр хитбокса.

## Коррекция движения → V2

Работает и со старыми ротациями. `Free`, `Focused` и `Target` не заменяются. Дополнительный переключатель виден только при выборе `V2`:

- **Скрытая** (по умолчанию внутри V2). Сохраняет направление, заданное клавишами относительно свободной камеры: выбирает ближайшее из восьми направлений WASD относительно фактического поворота игрока. Пример: камера смотрит прямо, Aura повернула игрока на 90° вправо. Нажатие `W` преобразуется в `A`, чтобы продолжать движение туда, куда смотрит камера. На диагонали скорость не увеличивается.
- **Прямая**. Оставляет клавиши как есть: в том же примере `W` ведёт вперёд относительно повёрнутого игрока. Это не автоматический подход к цели. В обоих вариантах ходьба и импульс спринт-прыжка используют поворот игрока; отдельного физического миксина не добавлено.

Без ввода движение не создаётся. Прыжок, приседание и спринт не подменяются. V2 не пересчитывает ввод при паузе, ручной установке блока или чужой задаче ротации. При потере цели управление возвращается штатной камере SkyCore: фоновые повороты без цели, дополнительные сетевые пакеты и подёргивание yaw из старого клиента не перенесены.

## Проверка

С JDK 25 из `sk 26.2`: `gradlew.bat testRockstarAura testAuraClicks` (Linux: `sh ./gradlew testRockstarAura testAuraClicks`). Обе задачи входят в `check`. Новый тест проверяет ключи режимов, сохранение/сброс угла OneTick, шаги по тику и кадру, чувствительность, ручной ввод и восемь направлений V2, в том числе переход через ±180°.

Для проверки в локальном мире: выберите разрешённую профилем цель, выключите `Client Look`, сравните `W` и диагонали в обоих вариантах V2. Затем проверьте `HolyWorld` с ручным движением мыши, смену цели, `Без поворота`, переключение на `ElytraTarget` в полёте и загрузку старого профиля. Названия режимов — названия донора, а не обещание результата на конкретном сервере.
