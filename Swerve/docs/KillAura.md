# KillAura: удары, криты и камера

Файлы:

| Файл | Что делает |
| --- | --- |
| `src/main/java/swerve/modules/impl/combat/KillAura.java` | цель, гейты удара, криты, режимы 1.8/1.9, FOV-индикатор |
| `src/main/java/swerve/utils/rotation/FreeLook.java` | свободный обзор и плавный догон камеры при молчаливой ротации |
| `src/main/java/swerve/utils/rotation/RotationController.java` | поворот тела, приоритеты, возврат камеры |
| `src/main/java/swerve/utils/combat/AuraUtils.java` | дистанция до хитбокса, угол от камеры, видимость точек |
| `tests/check_killaura.py` | статические регрессии по пунктам ниже |

## 1. Порядок проверок удара

`KillAura.updateAttack` (END_CLIENT_TICK, после тика игрока):

1. есть живая цель;
2. `manualAttack` — ручной режим, аура не бьёт;
3. `checkReturn` — «Не бить когда ешь» / «Бить только с оружием»;
4. `attackReady` — готовность оружия (см. §2);
5. `clickIntervalReady` — темп CPS для 1.8;
6. сброс спринта (нужен, чтобы удар засчитался критом);
7. `shouldAttack` — окно крита (см. §3);
8. `rayTraceOk` и `strictDistance < attackDistance`;
9. `shieldBreaker` — только после того, как удар уже разрешён;
10. `attackEntity` — пакеты удара и свинга.

Отложенных ударов в обход этих проверок нет: удаление `pendingCritTicks` важно,
иначе «Рандом криты» били мимо гейта крита.

## 2. Режимы 1.8 и 1.9

| | 1.8 | 1.9 |
| --- | --- | --- |
| Лимит темпа | CPS из настройки (`8..20`, разброс `0.8..1.2`, не чаще 1 удара за тик) | полная перезарядка оружия |
| Проверка | `clickIntervalReady()` | `player.getAttackStrengthScale(0.5F) >= 1.0F` |
| Порядок пакетов | swing → attack | attack → swing |
| «Кастомный меч» | не действует | дополнительная пауза поверх перезарядки |

Ванильная шкала перезарядки — единственный корректный способ «бить после полной
перезарядки»: у меча цикл 12.5 тика, у топора зависит от `ATTACK_SPEED`, у руки 5.
Жёсткие миллисекунды Private (250/450/550/850) не совпадали с этими значениями.

## 3. «Только криты»

`critWindow` повторяет ванильные условия крита из `Player.attack`:

- `fallDistance > 0`, `!onGround`, `!onClimbable`, `!isInWater`;
- без слепоты, не пассажир, не в спринте;
- дополнительно блокеры Private: левитация, паутина, элитра.

Наземных исключений нет: `!onGround` — обязательное условие. Удалены три обхода,
из-за которых аура била с земли:

- «Умные криты» (`onGround && verticalCollision`) — настройка удалена;
- удар в жидкости и на элитре возвращал `true` до проверок;
- «Рандом криты» с шансом 30 % игнорировали все условия.

«Рандом криты» остались как человекоподобность: 30 % окон крита намеренно
пропускаются, наземный удар при этом невозможен.

## 4. Камера

`FreeLook.turn` получает дельты из `MouseHandler.turnPlayer` **до** множителя
`Entity.turn`. Ванильный метод умножает обе оси на `0.15`; перехват обязан делать
то же, иначе свободный обзор крутится в 6.67 раза быстрее мыши — это и было
«камера слишком быстро двигается» при включённой ауре.

Догон камеры к телу («Камера: Догоняет»):

- старт через 400 мс после последнего движения мыши;
- доля оставшегося угла `3.0/с` и потолок `220°/с`;
- после `stopRotation` углы тела сливаются с камерой — обзор не прыгает.

Режимы камеры: «Догоняет» (по умолчанию), «Свободная» (камера целиком за мышью),
«Всегда на цели» (видимая ротация, камера = тело).

## 5. Что удалено

| Удалено | Причина |
| --- | --- |
| `PerfectDelay`, `events/network/PacketSendEvent`, `mixins/network/MixinConnection` | свои же `ServerboundSwingPacket` откладывали следующий удар на 450 мс, смена предмета — на 550 мс. Перезарядка и сброс тикера при смене предмета уже покрывают это ванильно |
| «Умные криты» | единственная наземная ветка крита |
| `pendingCritTicks`, `canCrit`, `lastRequiredFallDistance` | отложенный удар в обход гейтов |
| `dynamicCooldown`/`baseCooldown` | жёсткие миллисекунды вместо `ATTACK_SPEED` |
| креативная дистанция 6.0 | в 1.21.4 сервер считает `ENTITY_INTERACTION_RANGE + 3.0` |

## 6. Настройки

| Настройка | Значения | Смысл |
| --- | --- | --- |
| «Ручные удары (без автобоя)» | вкл/выкл, по умолчанию выкл | аура наводит тело, удар делает игрок кликом |
| «Режим кулдауна» | «Ванильный», «Кастомный меч» | 1.9: полная перезарядка + опциональная пауза |
| «Кулдаун меча (мс)» | 50..1000 | дополнительная пауза в режиме «Кастомный меч» |
| «CPS (1.8)» | 8..20 | темп ударов режима 1.8 |
| «Рандом криты» | вкл/выкл | пропуск 30 % окон крита |
| «Синхронизация по TPS» | вкл/выкл, по умолчанию выкл | темп удара подстраивается под лагующий сервер |
| «Множитель TPS» | 0..1, по умолчанию 0.5 | доля коррекции: 0.5 = половина недополученных тиков |
| «Не бить через блоки» | вкл/выкл | удар только при прямой видимости цели |
| «Улучшить хитбоксы» | вкл/выкл | вместо центра цели — 9 точек на видимой грани AABB |

Эти четыре настройки связаны: «Улучшить хитбоксы» меняет способ проверки видимости,
поэтому обязан проверять стену сам — иначе включение одной настройки отключает
другую. Разбор — `docs/PvPMath.md` §3.4.

Коррекция по TPS опирается на период пакета времени сервера: `ClientboundSetTimePacket`
уходит раз в 20 тиков (проверено по байткоду `MinecraftServer.tickChildren`), поэтому
`ServerTPS` измеряет лаг на шкале 20 TPS и игнорирует паузы короче 20 периодов пакета.
Раньше порог был равен одному периоду — ровно тому интервалу, на котором сервер и
начинает лагать, поэтому выборка пустела и TPS стоял на 20. Подробности —
`docs/PvPMath.md` §3.1.

## 7. Проверки

```bash
python3 Swerve/tests/check_killaura.py     # регрессии из этой статьи
python3 Swerve/tests/check_mc_api.py       # символы и миксины против 1.21.4
python3 Swerve/tests/check_scope.py        # «используется, но не объявлено»
python3 Swerve/tests/check_config.py       # конфиг и настройки модулей
python3 Swerve/tests/check_pvp_utils.py     # GCD, повороты, сравнение углов, видимость
python3 Swerve/tests/check_syntax.py       # разбор всех 220 файлов (tree-sitter-java)
```

Gradle-сборка и запуск клиента здесь невозможны: в песочнице нет JDK, а загрузка
дистрибутива упирается в сетевые ограничения (`curl` 35 на редирект release-ассетов),
поэтому про «компиляцию» тут говорить нечего — единственный воспроизводимый контроль
это перечисленные выше скрипты плюс `check_syntax.py`. Поведение критов, порядок
пакетов и ощущения камеры подтверждены разбором ванильного байткода 1.21.4
(`Entity.turn`, `Player.attack`, `Player.getAttackStrengthScale`,
`ServerGamePacketListenerImpl.handleInteract`), а не запуском игры; проверка
`check_elytra_flight_parity.py` требует `javac` и в этой среде останавливается на
отсутствии компилятора (код 2).

Само качество разбора тоже проверено: `python3 Swerve/tests/mc_disasm.py --selftest
100000` проходит весь jar (5744 класса, 59 968 методов) без неизвестных Opcode'ов и
без рассинхронизации в конце кода.
