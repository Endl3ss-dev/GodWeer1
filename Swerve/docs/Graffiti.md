# Graffiti

Основной файл: `Swerve/src/main/java/swerve/modules/impl/render/Graffiti.java`
Пакет фичи: `Swerve/src/main/java/swerve/graffiti/` (`GraffitiDesign`, `GraffitiSpot`, `GraffitiWorld`, `GraffitiQuad`, `GraffitiGhost`, `GraffitiStore`, `GraffitiRenderer`)
Миксины: `MixinMinecraft` → `startUseItem`, `MixinMouseHandler` → `onPress`
Категория: `RENDER`
Регистрация: `swerve.managers.ModuleManager` → `register(new Graffiti())`
Текстуры: `Swerve/src/main/resources/assets/swerve/textures/graffiti/*.png` (256x256 RGBA)
Хранилище: `config/swerve/graffiti.json`

## 1. Поведение

Модуль ставит **одно** граффити размером ровно **1x1 блок** на грань блока.

### Призрак под прицелом
Пока прицел смотрит на подходящую грань, на ней полупрозрачным (альфа 0.42)
показан выбранный рисунок — это предпросмотр того, куда он встанет.

- Прицел переехал на соседний блок — призрак **плавно и быстро** перелетает
  туда: экспоненциальное сглаживание `t = 1 - e^(-25·dt)`, около 95 % пути
  за 0.12 с. Поза интерполируется вместе с базисом грани, поэтому переход
  «стена → пол» читается как перенос по дуге, а не как прыжок.
- Шаг берётся из `Minecraft.getFrameTimeNs()`, а не из тика: при 20 тиках
  в секунду движение выглядело бы ступеньками.
- Прицел ушёл в воздух — призрак гаснет и забывает позу (следующая цель
  появляется на месте, без полёта через полмира).
- На той грани, где рисунок уже стоит, призрак не рисуется: два квада в одной
  плоскости давали бы двойную яркость и грязную кромку.

### Одна установка за 30 секунд
`Кулдаун` (по умолчанию 30 с) ограничивает установку. Пока таймер идёт:

- призрак тускнеет (альфа ×0.55, оттенок уходит в серый) — видно, что ставить нельзя;
- под прицелом горит индикатор: название рисунка и обратный отсчёт с полосой прогресса;
- клик **не отменяет ванильное действие**: блок ставится, еда съедается как обычно,
  а в уведомлениях появляется «рисунок ещё не готов» (текст без секунд, чтобы
  уведомление не плодилось на каждое нажатие).

### Одно граффити в мире
Установка в новом месте снимает прежний рисунок: он исчезает там, где был,
и появляется на новой грани с коротким проявлением (300 мс: альфа 0.30→1,
размер 78 %→100 %). Перерисовка той же грани с другим рисунком — тоже «перенос».

### Прочее
- `Бинд стирания` убирает рисунок из мира.
- Блок сломали — рисунок снимается сам.
- Рисунки привязаны к миру (`singleplayer` / `mp:<ip>`) и к измерению.

### Настройки (значения по умолчанию)

- `Рисунок` = `Скетч` (`Тег SWERVE` / `Кот` / `Череп` / `Смайл` / `Скетч`).
- `Активация` = `Присед + ПКМ` (`Присед + ПКМ` / `ПКМ` / `Бинд`).
- `Бинд рисования` = `n/a` (видно только в режиме `Бинд`).
- `Бинд стирания` = `n/a`.
- `Поворот` = `0°` (0…345, шаг 15).
- `Дистанция` = `4.5` блока (1…8, шаг 0.5) — предел, дальше прицел не рисует.
- `Кулдаун` = `30` с (5…120, шаг 5).
- `Прозрачность` = `0.92` (0.3…1.0) — для установленного рисунка.
- `Освещение` = `true` — рисунок темнеет вместе с гранью, но не ниже 45 % яркости.

## 2. Почему рисунки видны только у себя

Рисунки живут в клиенте и в сеть не уходят. Отправка требовала бы собственного канала
и мода на сервере: в ванильном протоколе для этого нет пакета, а Fabric-клиент не может
«дописать» чужие данные в пакеты без серверной поддержки. Так же устроены `Trails`
и `ChinaHat`.

Что это даёт:

- клиент не отправляет ни одного пакета — ни при нанесении, ни при стирании;
- ничего не меняется в мире: блоки, хитбоксы и данные чанков не трогаются;
- права на сервере не важны, работает и на «ванильном» сервере без плагинов.

Что это не даёт: другие игроки рисунков не видят. Если нужна общая картина — это уже
другая задача: серверный мод + `CustomPayload`-канал.

## 3. Ввод: почему перехват в `startUseItem`

ПКМ в ванилле — это «использовать предмет»: поставить блок, съесть еду, дёрнуть рычаг.
Тиковый опрос кнопки (`KeyMapping.isDown`) для рисования не годится: клик пришлось бы
отменять в другом месте, и вместе с граффити поставился бы блок.

Поэтому точка перехвата одна — `Minecraft.startUseItem` (`MixinMinecraft`):

```java
@Inject(method = "startUseItem", at = @At("HEAD"), cancellable = true)
private void swerve$graffitiUse(CallbackInfo ci) {
    Graffiti graffiti = ModuleManager.get(Graffiti.class);
    if (graffiti != null && graffiti.onVanillaUse()) {
        ci.cancel();
    }
}
```

- `onVanillaUse()` возвращает `true` **только если рисунок действительно поставлен**;
  не подошла грань, далеко, идёт кулдаун — ПКМ уходит в ваниллу как обычно;
- «свежесть» нажатия считают два источника, оба только поднимают флаг:
  хук `MixinMouseHandler.onPress` (быстрый клик успевает отпуститься между тиками)
  и опрос в `START_CLIENT_TICK` (страховка, если «использовать» переназначили на клавишу);
- флаг гасится в `END_CLIENT_TICK`: клик без цели не «выстрелит» позже, когда игрок
  просто присядет и нажмёт ПКМ.

Порядок тика в 1.21.4: `START_CLIENT_TICK` → `handleKeybinds` (`startUseItem`) →
`END_CLIENT_TICK`.

## 4. Рендер

`GraffitiRenderer` рисует квад 1x1 по грани, сдвинутый наружу на 0.0035 блока:
без сдвига на дальних дистанциях рисунок «мигает» вместе с гранью из-за точности
буфера глубины.

Поза грани — `GraffitiQuad`: {@code center}, {@code right}, {@code down}, {@code normal}.

- `right` — «вправо» для зрителя: `cross(forward, up)`, где `forward` смотрит в блок;
- `down = right × normal`;
- поворот `spin` вращает `right` вокруг нормали (формула Родрига), `down`
  пересчитывается — картинка не выходит из плоскости грани;
- на полу и потолке рисунок встаёт **низом к игроку** (как ванильные таблички):
  угол берётся от `getDirection()` (целые 90°), а не от точного yaw — иначе рисунок
  крутился бы вслед за мышью; настройка `Поворот` работает как смещение.
  Призрак считает тот же угол, поэтому превью всегда совпадает с результатом;
- `GraffitiQuad.interpolate` — поза между двумя гранями: центр по дуге
  (`sin(πt) · 0.35 · расстояние`), нормаль доворачивается smoothstep-шагом,
  базис — лерп + ортогонализация Грама — Шмидта;
- на перелёте «стена → пол» квад на середине пути повёрнут ребром к камере:
  в этом ракурсе рисунок гасится по косинусу между нормалью и направлением
  на камеру (`EDGE_HIDE_BELOW` / `EDGE_FULL_ABOVE`), а не растягивается
  в полоску.

Яркость, прозрачность и оттенок идут в цвете вершин — шейдер не нужен, используется
ванильный `CoreShaders.POSITION_TEX_COLOR`. Событие — `WorldRenderEvents.AFTER_TRANSLUCENT`
(как у `Trails`): рисунок рисуется после воды и стекла, но до частиц.

## 5. Хранилище

`config/swerve/graffiti.json`, отдельно от `config.json`. Модель — **одна запись на мир**
(карта `мир → рисунок`, измерение хранится внутри записи).

```json
{
  "format": 1,
  "worlds": {
    "singleplayer": {
      "minecraft:overworld": [
        {"x": 12, "y": 70, "z": -4, "face": "north", "design": "SKETCH", "spin": 0.0, "at": 1700000000000}
      ]
    }
  }
}
```

- Ключ мира: `singleplayer` (интегрированный сервер) или `mp:<ip>`. Рисунок,
  поставленный на сервере, не всплывает в одиночке.
- Структура файла (мир → измерение → массив) оставлена прежней; файл от версии
  с несколькими рисунками читается и схлопывается до самого свежего на мир.
- Запись атомарная: сначала `graffiti.json.tmp`, затем `move`; отложенная — через
  0.8 с после правки, немедленная при выключении модуля.
- Проверка «блок и его открытая грань ещё на месте» идёт только в том измерении,
  где лежит рисунок: иначе переход через портал стирал бы запись по чужим координатам.
- Битые записи (неизвестный рисунок, грань, нечисловые координаты) пропускаются.

## 6. Текстуры

Все рисунки — 256x256 RGBA с прозрачным фоном, нарисованы/обработаны под этот модуль
(белый фон снят, кромка сглажена, рисунок вписан в квадрат с отступом 6 %). Благодаря
этому квадрат 1x1 блока закрашивается целиком без искажения пропорций.

| Файл | Подпись в меню |
|------|----------------|
| `tag.png` | Тег SWERVE |
| `cat.png` | Кот |
| `skull.png` | Череп |
| `smiley.png` | Смайл |
| `1.png` | Скетч |

`1.png` — карандашный скетч: с исходного JPEG снята бумага страницы (заливка от края
кадра по чистому белому), фигура осталась непрозрачной «наклейкой», светлая штриховка
рубашки сохранена полупрозрачными пикселями, контраст подтянут, чтобы линии читались
и на тёмном, и на светлом блоке.

Новый рисунок добавляется двумя шагами: положить PNG в ту же папку и добавить
константу в `GraffitiDesign` (её имя попадёт в файл хранилища).

## 7. Проверки

- `python3 Swerve/tests/check_mc_api.py` — импорты, цели миксинов, сигнатуры колбэков,
  статические вызовы, в том числе новые классы `swerve.graffiti.*`.
- `python3 Swerve/tests/check_scope.py Swerve/src/main/java` — области видимости.
- `python3 Swerve/tests/check_config.py` — уникальность имён настроек и ключей модулей.
- `./gradlew compileJava` в песочнице без JDK не запускался: JDK в окружении нет,
  а зависимости Loom (Mixin, Gson, JOML, LWJGL) недоступны офлайн. Проверка API
  выполнена статически по байткоду `minecraft-merged 1.21.4`.
