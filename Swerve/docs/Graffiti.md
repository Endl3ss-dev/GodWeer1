# Graffiti

Основной файл: `Swerve/src/main/java/swerve/modules/impl/render/Graffiti.java`
Пакет фичи: `Swerve/src/main/java/swerve/graffiti/`
Миксин: `Swerve/src/main/java/swerve/mixins/client/MixinMinecraft.java` → `startUseItem`
Категория: `RENDER`
Регистрация: `swerve.managers.ModuleManager` → `register(new Graffiti())`
Текстуры: `Swerve/src/main/resources/assets/swerve/textures/graffiti/*.png` (256x256 RGBA)
Хранилище: `config/swerve/graffiti.json`

## 1. Поведение

Модуль наносит рисунок размером ровно **1x1 блок** на грань блока, в которую смотрит прицел.

- ПКМ при зажатом приседе (по умолчанию), обычный ПКМ (режим «ПКМ») или бинд (режим «Бинд»).
- Рисунок «приклеен» к грани: виден только с её стороны, повторное нанесение на ту же
  грань перерисовывает её (другой рисунок или другой поворот).
- Поворот (`Поворот`) задаётся шагом 15° — рисунок вращается вокруг нормали грани,
  поэтому «шапка» картинки всегда остаётся в плоскости блока.
- Новый рисунок проявляется за 320 мс: прозрачность от 0.35 к полной, размер
  от 74 % к 100 %. Это единственная анимация — она показывает, что клик сработал.
- Блок сломали (или он исчез, или его грань закрыли) — запись снимается в тике.
- Биндинг «Бинд стирания» убирает рисунок с грани под прицелом.
- Не больше 512 рисунков на мир (`GraffitiStore.MAX_PER_WORLD`); при переполнении
  в уведомлениях появляется предупреждение, а новый рисунок не ставится.

### Настройки (значения по умолчанию)

- `Рисунок` = `Тег SWERVE` (`Тег SWERVE` / `Кот` / `Череп` / `Смайл`).
- `Активация` = `Присед + ПКМ` (`Присед + ПКМ` / `ПКМ` / `Бинд`).
- `Бинд рисования` = `n/a` (видно только в режиме `Бинд`).
- `Бинд стирания` = `n/a`.
- `Поворот` = `0°` (0…345, шаг 15).
- `Дистанция` = `4.5` блока (1…8, шаг 0.5) — предел, дальше прицел не рисует.
- `Прозрачность` = `0.9` (0.1…1.0).
- `Освещение` = `true` — рисунок темнеет вместе с гранью (но не ниже 42 % яркости,
  иначе в пещере он превращался бы в чёрный квадрат).
- `Подсветка грани` = `true` — грань под прицелом подсвечивается цветом темы.

## 2. Почему рисунки видны только у себя

Рисунки живут в клиенте и в сеть не уходят. Отправка требовала бы собственного канала
и мода на сервере: в ванильном протоколе для этого нет пакета, а Fabric-клиент не может
«дописать» чужие данные в пакеты без серверной поддержки. Так же устроены `Trails`
и `ChinaHat`.

Что это даёт:

- клиент не отправляет ни одного пакета — ни при нанесении, ни при стирании;
- ничего не меняется в мире: блоки, хитбоксы и данные чанков не трогаются;
- права на сервере не важны, работает и на «ванильном» сервере без плагинов.

Что это не даёт: другие игроки рисунков не видят. Если нужна общая картина — это уже
другая задача: серверный мод + `CustomPayload`-канал.

## 3. Ввод: почему перехват в `startUseItem`

ПКМ в ванилле — это «использовать предмет»: поставить блок, съесть еду, дёрнуть рычаг.
Тиковый опрос кнопки (`KeyMapping.isDown`) для рисования не годится: клик пришлось бы
отменять в другом месте, и вместе с граффити поставился бы блок.

Поэтому точка перехвата одна — `Minecraft.startUseItem` (`MixinMinecraft`):

```java
@Inject(method = "startUseItem", at = @At("HEAD"), cancellable = true)
private void swerve$graffitiUse(CallbackInfo ci) {
    Graffiti graffiti = ModuleManager.get(Graffiti.class);
    if (graffiti != null && graffiti.onVanillaUse()) {
        ci.cancel();
    }
}
```

- `onVanillaUse()` возвращает `true` **только если рисунок действительно нанесён**;
  не подошла грань, далеко, занято, достигнут лимит — ПКМ уходит в ваниллу как обычно;
- «свежесть» нажатия считает `ClientTickEvents.START_CLIENT_TICK`: событие идёт до
  `Minecraft.handleKeybinds`, поэтому в том же тике `startUseItem` уже видит,
  что кнопку только что нажали. Удержание не рисует каждый тик;
- повторный вход отсекает кулдаун 180 мс (`PLACE_COOLDOWN_MS`).

Порядок тика в 1.21.4: `START_CLIENT_TICK` → `handleKeybinds` (`startUseItem`) →
`END_CLIENT_TICK`.

## 4. Рендер

`GraffitiRenderer` рисует квад 1x1 по грани, сдвинутый наружу на 0.0035 блока:
без сдвига на дальних дистанциях рисунок «мигает» вместе с гранью из-за точности
буфера глубины.

База плоскости грани:

- `u` — «вправо» для зрителя: `cross(forward, up)`, где `forward` смотрит в блок;
- `v = u × n` — «вниз» картинки;
- поворот `spin` вращает `u` вокруг `n` (формула Родрига), `v` пересчитывается.

Для пола и потолка «верх» картинки всегда смотрит на север (правило фиксированное),
поэтому рисунок на полу не поворачивается вслед за камерой.

Батчинг: квады группируются по рисунку (`EnumMap<GraffitiDesign, BufferBuilder>`),
текстура биндится один раз на рисунок. Яркость, прозрачность и проявление идут
в цвете вершин — шейдер не нужен, используется ванильный
`CoreShaders.POSITION_TEX_COLOR`. Дистанционное затухание начинается с 82 % от
дальности прорисовки.

Событие — `WorldRenderEvents.AFTER_TRANSLUCENT` (как у `Trails`): рисунок рисуется
после воды и стекла, но до частиц.

## 5. Хранилище

`config/swerve/graffiti.json`, отдельно от `config.json`: записей много, и они меняются
независимо от настроек модуля.

```json
{
  "format": 1,
  "worlds": {
    "singleplayer": {
      "minecraft:overworld": [
        {"x": 12, "y": 70, "z": -4, "face": "north", "design": "CAT", "spin": 90.0, "at": 1700000000000}
      ]
    }
  }
}
```

- Ключ мира: `singleplayer` (интегрированный сервер) или `mp:<ip>`; ключ измерения —
  `minecraft:overworld` и т.п. Рисунок, нанесённый на сервере, не всплывает в одиночке.
- Запись атомарная: сначала `graffiti.json.tmp`, затем `move`.
- Запись отложенная: через 1.5 с после правки, в тике; при выключении модуля и выходе
  из игры — сразу (`onDisable`).
- Битые записи (неизвестный рисунок, грань, нечисловые координаты) пропускаются
  по одной, остальные читаются.
- Проверка «грань ещё существует» идёт порциями по 64 записи за тик по кругу
  (курсор `pruneCursor`), чтобы обход большого полотна не съедал кадр.

## 6. Текстуры

Все рисунки — 256x256 RGBA с прозрачным фоном, нарисованы под этот модуль
(белый фон снят, кромка сглажена в premultiplied-пространстве, рисунок вписан
в квадрат с отступом 6 %). Благодаря этому квадрат 1x1 блока закрашивается целиком
без искажения пропорций.

| Файл | Подпись в меню |
|------|----------------|
| `tag.png` | Тег SWERVE |
| `cat.png` | Кот |
| `skull.png` | Череп |
| `smiley.png` | Смайл |

Новый рисунок добавляется двумя шагами: положить PNG в ту же папку и добавить
константу в `GraffitiDesign` (её имя попадёт в файл хранилища).

## 7. Проверки

- `python3 Swerve/tests/check_mc_api.py` — импорты, цели миксинов, сигнатуры колбэков,
  статические вызовы, в том числе новые классы `swerve.graffiti.*`.
- `python3 Swerve/tests/check_scope.py Swerve/src/main/java` — области видимости.
- `python3 Swerve/tests/check_config.py` — уникальность имён настроек и ключей модулей.
- `./gradlew compileJava` в песочнице без JDK не запускался: JDK в окружении нет,
  а зависимости Loom (Mixin, Gson, JOML, LWJGL) недоступны офлайн. Проверка API
  выполнена статически по байткоду `minecraft-merged 1.21.4`.
