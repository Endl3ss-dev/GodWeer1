# Конфиг клиента

Основные файлы:

| Файл | Назначение |
| --- | --- |
| `src/main/java/swerve/config/ConfigManager.java` | загрузка, сохранение, автосохранение, формат |
| `src/main/java/swerve/config/SettingCodec.java` | значение одной настройки ⇄ JSON |
| `src/main/java/swerve/modules/Module.java` | `setEnabledQuiet`, пометка конфига изменённым |
| `src/main/java/swerve/ui/menu/MenuScreen.java` | пометка изменений и сброс на диск при закрытии меню |
| `src/main/java/swerve/Swerve.java` | `ConfigManager.init()` после `ModuleManager.init()` |

## 1. Что сохраняется

- включённость каждого модуля (`enabled`);
- бинд модуля (`key`, в том же числовом формате, что и `KeyBoardUtils`: клавиша GLFW
  или `1000 + кнопка мыши`);
- значения всех настроек модуля: `BooleanSetting`, `FloatSetting`, `ModeSetting`,
  `ListSetting`, `TextSetting`, `BindSetting`;
- настройки GUI (`GuiConfig`: сила блюра панелей, сила блюра настроек, прозрачность фона);
- настройки меню (`MenuPrefs`: звуки, громкость, блюр, затемнение, градиенты, анимации,
  скорость анимаций, масштаб) и номер палитры (`MenuTheme.palette`).

Позиции HUD-элементов **не** дублируются: они уже лежат в `swerve/hud.json`
(`HudPositionStore`, запись по окончании перетаскивания). Друзья — `swerve/friends.json`,
косметика — `swerve/cosmetics.json`.

Исключение — `ViewModel`: раскладка рук и её настройки (`Сила`, `Скорость`, `Анимация`,
`Обводка силуэта`, `Размер обводки`, `Только при наводке`) уже пишутся его собственным
асинхронным писателем в `swerve/viewmodel.json` и читаются в `onEnable`. Модуль
переопределяет `Module.usesOwnConfig()` → `true`, и общий конфиг хранит для него только
`enabled` и `key`. Дублировать значения было бы нельзя: при включении модуль всё равно
прочитал бы свой файл и перезаписал их — получилось бы два источника правды.

## 2. Файл и формат

Путь: `<game dir>/config/swerve/config.json` (`FabricLoader.getConfigDir()`).

```json
{
  "format": 1,
  "client": "Swerve",
  "modules": {
    "KillAura": {
      "enabled": true,
      "key": 82,
      "settings": {
        "Дистанция": 3.0,
        "Цель": "Все",
        "Учитывать": {"Игроки": true, "Мобы": false},
        "Через стены": false,
        "Приоритет": 45
      }
    }
  },
  "gui": {"blur": 8.5, "settingsBlur": 8.5, "backgroundAlpha": 0.0},
  "menu": {
    "sounds": true, "volume": 70.0, "hoverSounds": true, "sliderSounds": true,
    "blur": true, "dim": 40.0, "gradient": true, "animations": true,
    "animSpeed": 1.0, "scale": 100.0, "palette": 0
  }
}
```

Правила ключей:

- **модуль** — простое имя класса (`KillAura`, `ArrayListHud`), а не отображаемое имя:
  переименование модуля в UI не теряет его настройки. Обратная сторона: переименование
  *класса* модуля сбрасывает его настройки один раз;
- **настройка** — её `name()` (то, что видно в меню). Вставка новой настройки в середину
  списка значения соседних не сдвигает. Одинаковые имена внутри одного модуля делят одно
  значение — таких модулей нет, это проверяет `tests/check_config.py`;
- файл правится руками: числа обрезаются по границам настройки, неизвестный режим
  отбрасывается, длинный текст обрезается по `maxLength`, значения неверного типа
  игнорируются. Сломать запуск правкой файла нельзя.

`format` — версия схемы. Файл с другой версией игнорируется целиком (клиент стартует
с дефолтами), поэтому будущая миграция не обязана читать старые поля.

## 3. Когда пишется на диск

1. `Module.setEnabled` (биндинг, клик в меню, программное выключение) — `markDirty()`;
2. любое действие в меню (`runAction`), перетаскивание ползунка настройки
   (`applySlider`) и ползунка префа (`applyPrefSlider`) — `markDirty()`;
3. автосохранение в `END_CLIENT_TICK`, не чаще одного раза в 2 с
   (`SAVE_INTERVAL_MS`) и только при поднятом флаге;
4. закрытие меню — `saveIfDirty()` сразу;
5. выход из игры — `ClientLifecycleEvents.CLIENT_STOPPING` → `saveIfDirty()`.

В кадре рендера обращений к файлу нет. В тике — только проверка двух полей
(`dirty`, время последней записи). Запись выполняется один раз на пачку правок.

`save()` сравнивает сериализованный текст с последним записанным и в случае совпадения
файл не трогает: клик по вкладке меню, ничего не изменивший, не переписывает конфиг.

Запись атомарная: сначала `config.json.tmp`, затем `Files.move(..., ATOMIC_MOVE)`
с откатом на обычную замену, если ФС не умеет атомарный перенос. Падение игры
в момент сохранения не оставит половину JSON.

## 4. Как читается

`ConfigManager.init()` вызывается из `Swerve.onInitializeClient()` сразу после
`ModuleManager.init()`: до регистрации модулей восстанавливать нечего.

Порядок применения для модуля: сначала настройки, потом бинд, потом включение —
`onEnable()` видит уже восстановленные значения. Включение идёт через
`Module.setEnabledQuiet`, поэтому запуск клиента не сопровождается пачкой уведомлений
«модуль включён». Пользовательские тоглы (`setEnabled`) уведомление показывают и
помечают конфиг изменённым.

Модули из файла, которых в клиенте больше нет, игнорируются и исчезают при следующем
сохранении. Так же ведут себя исчезнувшие настройки.

## 5. Краевые случаи

| Ситуация | Поведение |
| --- | --- |
| файла нет | дефолты, файл не создаётся до первой правки |
| пустой/битый JSON | `warn` в лог, дефолты; следующая правка перезапишет файл валидным |
| `format` другой версии | файл игнорируется целиком |
| неизвестный модуль или настройка | игнорируется |
| число вне границ | обрезается сеттером настройки |
| `onEnable` модуля бросает исключение | модуль остаётся выключенным, остальные восстанавливаются |
| `onDisable` бросает исключение | логируется, наружу не выходит |
| нет прав на запись в каталог | `warn`, флаг `dirty` остаётся — попытка повторится |
| несколько клиентов на одном конфиге | последняя запись побеждает (файл не блокируется) |

## 6. Проверки

Статическая (без JDK, воспроизводима):

```bash
python3 Swerve/tests/check_config.py
```

Проверяет симметрию ключей сохранения и загрузки для `gui`/`menu`, покрытие всех полей
`MenuPrefs` и `GuiConfig`, ветки `SettingCodec` для всех типов настроек, учёт
`usesOwnConfig()` в обе стороны, `setEnabledQuiet` при восстановлении, `markDirty` под
`if (notify)`, точки правки в меню, порядок инициализации, уникальность ключей модулей
и имён настроек, отсутствие `net.minecraft.*` в пакете `config`. Негативные прогоны (искусственно сломанные копии дерева) дают
ожидаемые находки.

Компиляция всего дерева (180 файлов → 203 класса) выполнена ECJ 3.46.0
(`org.eclipse.jdt.core.compiler.batch`) с `-source 21 -target 21` против реального
`minecraft-merged-a172fc6613-1.21.4` из loom-кэша и реальных `fabric-api 0.119.4+1.21.4`
jar из кэша. Для библиотек, которых нет в песочнице, использованы заглушки компиляции
(Gson — только сигнатуры используемых классов, LWJGL GLFW/GL11/GL12/GL30, миксины
и MixinExtras, fastutil, slf4j, fabric-loader); JOML собран из исходников 1.10.5.

Поведение проверено отдельным харнессом (`ConfigHarness`, 57 проверок) на настоящем
Gson 2.11.0 и настоящих классах настроек Swerve. Сценарии:

- файла нет; частичный конфиг; битый JSON; чужая версия формата;
- обрезка чисел по границам настройки и текста по `maxLength`;
- неизвестный модуль, настройка и тип значения;
- структура сохранённого файла (format/client/modules/gui/menu);
- восстановление после «перезапуска» и идемпотентная запись без правок;
- модуль со своим файлом настроек: общий конфиг хранит только `enabled` и `key`;
- модуль с падающим `onEnable` не мешает восстановлению соседнего;
- каталог без прав на запись: исключение не выходит наружу, флаг остаётся и запись
  проходит после восстановления прав.

Харнесс и заглушки в репозиторий не входят: они собираются из JDK-рантайма и ECJ,
которых в репозитории нет.

## 7. Ограничения

- один автосохраняемый профиль; именованных профилей (`configs/<name>.json`) и
  переключения из UI пока нет;
- кнопки «сбросить конфиг» в меню нет — сброс делается удалением файла;
- настройки читаются один раз при старте: правка `config.json` на лету не подхватывается;
- значения привязаны к именам (см. §2): переименование настройки в коде сбрасывает её
  сохранённое значение;
- запись не сбрасывается при аварийном завершении процесса (kill -9): теряются правки
  последних ~2 секунд;
- настройки `ViewModel` правятся и сохраняются его собственным файлом (см. §1): общий
  конфиг их не восстанавливает, поэтому правка `viewmodel.json` руками и `config.json`
  руками — независимые вещи.
