## 2. KillSay

Настройка одна — строка `Сообщение`, как и просили. В тексте работают подстановки:

- `{name}` — ник убитого;
- `{me}` — свой ник.

Убийство определяется по серверному сообщению в чате (те же пакеты, что слушает
`AutoMessage`): клиент не получает события «сущность умерла», а сообщение
«Вы убили …» есть на серверах, где включены такие уведомления. Маркеры: `вы убили`,
`ты убил`, `вы одолели`, `you killed`, `you have killed`, `you slayed`.
Повтор того же ника в пределах 1.5 с игнорируется — сервер иногда дублирует строку.

Пустая строка = ничего не отправлять.

## 3. DrinkUse (порт)

Сохранено из источника: выбор напитка, режим «по бинду» / «по окончанию кд», действие
ПКМ/ЛКМ, бинд, работа в GUI, задержка старта, кулдаун, «пакетный» режим, рука,
уведомления.

Адаптация под 26.2:

- клик по слоту — `gameMode.handleContainerInput(…, ContainerInput.SWAP, …)`
  (в 26.2 `ClickType` заменён на `ContainerInput`, кнопка 40 — левая рука), как в
  `InventoryHelper.swapHand`;
- смена слота — `InventoryHelper.selectHotbarSlot` (в 26.2 нет поля
  `inventory.selected`, есть `getSelectedSlot()/setSelectedSlot()`);
- экран проверяется через `gui.screen()`;
- распознавание головы — свой `util/DrinkItems` вместо `DrinkUtil`: в 26.2 профиль
  читается через `ResolvableProfile.partialProfile()`, `GameProfile.id()` не `Optional`,
  а свойства — `PropertyMap`.

После использования предмет возвращается на место (в «пакетном» режиме — двумя
свапами подряд, в режиме «Рука» — через состояние `USE → RESTORE`).

## 4. ItemSwap (порт)

Сохранено: два предмета (Чарка / Тотем / Щит / Арбалет), режимы «Цикл» и «Удержание»,
биндинг, задержка, поиск по хотбару или всему инвентарю, «пропускать если в руке»,
«не свапать при использовании», уведомление.

Адаптация: слот ищется прямо в `containerMenu.slots` по `slot.index` (9…44), свап —
`ContainerInput.SWAP` с кнопкой 40, уведомление — в чат.

## 5. SkinStealer

Настройки: `Ник цели` (строка), `Применить скин`, `История ников`,
`Уведомление об успехе`, `Уведомление об ошибке`.

Порядок работы:

1. ник уходит в `SkinService.prefetch` — скачивание идёт в фоновом потоке
   (Mojang API + crafatar), в кадре никакой сети;
2. каждый тик модуль проверяет `SkinService.skinIfReady(nick)` (новый метод: старый
   `skin()` возвращал заглушку Стива и не позволял отличить «готово» от «качается»);
3. готовую текстуру модуль превращает в `PlayerSkin` так же, как
   `TextureHashHelper.skinForId` (`PlayerSkin.insecure(new ClientAsset.DownloadedTexture(...),
   null, null, PlayerModelType.WIDE)`);
4. при включённом «Применить скин» этот `PlayerSkin` отдаёт миксин
   `AbstractClientPlayerSkinOverrideMixin` — и только для локального игрока;
5. ник печатается в чат строкой `SkinStealer: /skin <ник>`, чтобы им можно было
   воспользоваться серверной командой. Это и есть основной результат модуля;
6. при включённой истории ник дописывается в `skycore/skin-history.txt`
   (последние 50, без дублей).

Модуль ничего не рисует на экране — только сообщения в чат, как и просили.

Ограничения, которые лучше знать заранее:

- нужен интернет; при таймауте 12 с модуль пишет «ник не найден» (если включено
  уведомление об ошибке);
- модель скина всегда широкая: Slim определяется по подписи профиля, а у скачанного
  PNG её нет;
- миксин подключён с `require = 0`: если в вашей сборке 26.2 `getSkin()` объявлен
  выше по иерархии, подмена просто не включится, но клиент не упадёт — ник в чате
  продолжит работать.

## 6. FakePlayer

Модуль переписан: теперь это 33 настройки в меню (29 из них доезжают до болванки через
`FakePlayerConfig`; остальные четыре — имя, количество, дистанция спавна и авто-респавн —
нужны самому модулю). Сама болванка
по-прежнему живёт в `command/FakeplayerCommand.java`, а настройки до неё доезжают через
`combat/FakePlayerConfig.java` (снимок) и `combat/FakePlayerSettings.java` (текущий снимок).
Модуль собирает снимок каждый тик, поэтому настройки применяются на лету, без пересоздания
болванки.

|---|---|---|---|
| Кто и сколько | Имя бота | строка (16) | `FakePlayer` |
| | Кол-во ботов | число 1…10 | 1 |
| | Дистанция спавна | число 1…20 | 3.0 |
| | Авто-респавн | bool | вкл |
| Инвентарь | Копировать инвентарь | bool | выкл |

| Тотем | Использовать тотем | bool | вкл |
| | Режим тотема | `Legit / Normal / Hard / Extra` | Normal |
| | Кол-во тотемов | число 0…300 | 1 |
| | Бесконечные тотемы | bool | выкл |
| Щит | Использовать щит | bool | выкл |
| | Режим щита | `Legit / Normal / Hard / Extra` | Normal |

| | Регенерация | bool | выкл |

| | Огнестойкость / Сопротивление / Скорость | режимы `Off / I / II / III / IV` | Off |

| | Иммунитет к взрывам | bool | выкл |

Что означают режимы (одинаково для тотема и щита — «чем выше, тем труднее убить»):

| Режим | Тотем тратится при здоровье | Щит поднимается |
|---|---|---|
| Legit | ≤ 3 hp | в 4 блоках и только после попадания |
| Normal | ≤ 6 hp | в 6 блоках |
| Hard | ≤ 10 hp | в 12 блоках |
| Extra | ≤ 16 hp | всегда |

Как это работает на практике:

- **Кто и сколько.** Включение модуля создаёт нужное число болванок за спиной игрока;
  имена — `Имя`, `Имя2`, `Имя3`… Смена имени пересоздаёт болванок, «Кол-во ботов»
  добирает или убирает лишних, «Авто-респавн» поднимает убитую болванку снова.
- **Инвентарь.** «Копировать инвентарь» важнее остальных настроек группы: если он включён,
  берутся ваши броня и обе руки. Иначе — комплект из «Типа брони», на него кладётся
  Protection, в правую руку — «Предмет в руке», в левую — щит (если включён) либо тотем.
- **Тотем и щит.** Счётчик тотемов живёт на болванке; «Бесконечные тотемы» его не
  уменьшают. Если тотемы выключены или закончились — болванка умирает. Щит выдаётся в
  левую руку и поднимается обычным ванильным использованием левой руки.
- **Поведение.** «Следовать за игроком» подтягивает болванку к вам, если она дальше
  2.2 блока; «Стрейф» водит её по кругу, удерживая 2…3.5 блока. «Прыгать» — прыжок раз в
  секунду, пока болванка на земле.
- **Выживаемость.** «Здоровье (HP)» меняет максимальное HP болванки (и лечит её при
  изменении). «Регенерация» лечит 1 hp раз в «Тик регенерации». Эффекты обновляются
  каждую секунду, поэтому не гаснут. «Сопротивление» кроме иконки реально режет урон
  (20 % за уровень, максимум 80 %), «Скорость» — реально ускоряет движение (+20 % за
  уровень). Иммунитеты отсекают урон с тегами `IS_FIRE` / `IS_EXPLOSION`.
- **Бой.** Болванка бьёт ближайшую цель в 3.5 блока раз в 12 тиков. По фейк-игрокам урон
  настоящий (они целиком клиентские), по реальному игроку — только замах, поворот и звук:
  здоровье реального игрока считает сервер, клиент его изменить не может. «Есть при HP <» —
  имитация золотого яблока (лечение, регенерация, поглощение) раз в 32 тика.
- **Визуал и сеть.** «Невидимость» ставит флаг `setInvisible`, «Свечение» — эффект
  `GLOWING`. «Пинг (мс)» задерживает позицию игрока, по которой болванка целится и идёт:
  1000 мс = 20 тиков отставания, как у настоящего высокого пинга.

Отдельно поправлено по дороге: `getItemInHand(OFF_HAND)` больше не подменяет левую руку
тотемом всегда — раньше из-за этого щит не рисовался и не блокировал, а скопированный
предмет из инвентаря «исчезал». Тотем подставляется только если рука действительно пуста.

Болванки из `/fakeplayer add` не изменились: у них прежний незеритовый комплект с
починкой и тотемом, настройки модуля на них не влияют.

## 6a. Dinner Bone (переворот игрока)

Запрос: «переворачивать игрока, как DinnerBone, и чтобы это было видно другим игрокам
на чужом сервере».

### Честная физика вопроса

Переворот — **клиентский рендер**, а не эффект и не пакет: рендерер сущности смотрит на
имя и, если оно `Dinnerbone` или `Grumm`, переворачивает модель
(`LivingEntityRenderer` → флаг в рендер-состоянии → `translate(0, рост, 0) + rotate(180°, Z)`).
В протоколе Minecraft нет пакета «переверни меня», поэтому:

| Что | Видно другим игрокам | От чего зависит |
|---|---|---|
| Ник `Dinnerbone`/`Grumm` на сервере | **да** | сервер должен разрешить смену ника (и делать её пакетно, а не только в чате) |
| Локальный переворот (миксин) | нет, только вам | работает на любом сервере |

То есть «видно всем» на чужом сервере возможно **только** через ник: имя игрока —
серверные данные, клиент их не подменяет. Модуль делает обе вещи и честно говорит,
что получилось.

### Настройки

| Настройка | Тип | Значение |
|---|---|---|
| Способ | режим | `Ник + локально` (по умолчанию), `Только ник`, `Только локально` |
| Переворачивать локально | режим | `Себя`, `Себя и других` |
| Команды ника (через `;`) | строка | `/nick Dinnerbone;/nickname Dinnerbone;/setnick Dinnerbone;/nick set Dinnerbone;/nick Grumm` |
| Пауза между командами (мс) | число 1000…20000 | 4000 |
| Останавливаться после успеха | bool | вкл |
| Писать в чат | bool | вкл |
| Проверить ник | кнопка | показывает текущее имя и состояние локального переворота |
| Отправить команду сейчас | кнопка | отправляет следующую команду из списка, не дожидаясь паузы |

### Как работает вариант «Ник»

1. Раз в «Паузу между командами» отправляется следующая команда из списка.
2. После каждой попытки модуль сверяет ник в списке игроков (с учётом цветов и
   префиксов ранга: `[VIP] Dinnerbone` тоже считается) и настоящее имя профиля.
3. Как только ник стал `Dinnerbone`/`Grumm` — модуль сообщает об успехе и
   останавливается: дальше переворот делают клиенты **всех** игроков, включая ваш.
4. Если прошли все команды и ничего не изменилось — сообщение «сервер не дал ник»,
   и остаётся локальный вариант.

Список команд правится прямо в меню: если на вашем сервере ник делается иначе
(например, `/nick set <ник>`, `/nick <ник> &r` или через донат-меню), достаточно
дописать свою команду через `;`. Если сервер вообще не разрешает ник — обойти это
клиентом нельзя, это ограничение протокола, а не модуля.

### Как работает вариант «Локально»

`AvatarRendererDinnerboneMixin` (и запасной `LivingEntityRendererDinnerboneMixin`)
на выходе из `extractRenderState` ставят тот же флаг в рендер-состоянии, что и ваниль
для ника `Dinnerbone`. Дальше работает обычный ванильный код, поэтому картинка
совпадает с настоящим «Dinnerbone» один в один. Имя поля флага в разных версиях
разное, поэтому `util/DinnerboneFlip` ищет его рефлексией
(`isUpsideDown`, `flipUpsideDown`, затем любое boolean-поле с `upside`/`flip` в имени):
если поля нет — модуль пишет в чат, что локальный вариант в этой сборке недоступен,
и рендер не ломается.

### Риски, о которых стоит знать

- неизвестная команда на сервере — это запись в чат и, на некоторых серверах, мут за
  спам; поэтому пауза по умолчанию 4 секунды и одна попытка на команду;
- если сервер делает ник только «для чата» (без пакетной подмены в списке игроков),
  переворота не будет даже при успешном `/nick` — модуль об этом скажет, потому что
  сверяет именно имя в списке игроков;
- «Только ник» без успешного ника не даёт ничего: локальный переворот в этом режиме
  выключен намеренно, чтобы результат совпадал с ожиданием.

Не проверено в игре: `LivingEntity.startUsingItem(InteractionHand)` и `stopUsingItem()` для
щита болванки, `LivingEntity.jumpFromGround()`, `Entity.playSound(...)` на клиентской
болванке, `Level.players()` в клиентском мире, а также фактическое применение миксина
подмены скина — метод `getSkin()` в 26.2.

Что стоит проверить в игре первым делом:

1. `/fakeplayer add test` — у болванки должен быть прежний незеритовый комплект и тотем;
2. включить модуль с `Кол-во ботов = 2` — появятся две болванки за спиной и не будет
   спама «Spawned …» в чате;
3. «Следовать за игроком» + «Прыгать» — болванка должна идти и подпрыгивать, а не
   «плыть» (для болванок модуля принудительное `setSwimming` отключено);
4. «Использовать щит» — щит должен быть виден в левой руке и подниматься; если нет,
   значит в вашей сборке 26.2 иначе называется `getItemInHand` — пришлите лог.

## 8. Spear Dash — «огромный удар» копьём (2026-10-29)

Задача: можно ли сделать модуль, который ваншотит игроков копьём через атаку Dash
(в русской локализации зачарование называется «Рывок», в английском — Lunge).

### Механика, из которой растёт модуль

| Факт | Значение | Источник |
|---|---|---|
| «Рывок» (Lunge I–III) | только на копьё; джаб даёт импульс `0.458 × N` блоков/тик по взгляду; в воздухе дальше; максимум при горизонтальном прицеле | [minecraft.wiki/w/Lunge](https://minecraft.wiki/w/Lunge) |
| Цена рывка | `4 × N` истощения + 1 прочность; не работает в воде, на элитре, верхом и при еде < 7 | там же |
| Урон заряда | `floor(множитель × скорость сближения, бл/с)` + урон атрибутов и зачарований; порог 4.6 бл/с, нокбек при своих ≥ 5.1 | [minecraft.wiki/w/Spear](https://minecraft.wiki/w/Spear) |
| Множители | дерево/золото 0.7, камень/медь 0.82, железо 0.95, алмаз 1.075, незерит 1.2 | там же |
| Дальность копья | от 2 до 4.5 блоков, ближе 2 — не бьёт вообще | там же |
| Связка | «Рывок» не усиливает урон сам, но если сразу после джаба начать заряд, заряд доезжает на скорости рывка: **незерит + Рывок III ≈ 33 урона** (16.5 сердец) | таблица «Charge attack damage comparisons» на вики |

Вывод для пользователя: «ваншот» копьем — это не умножение урона клиентом (его нет и
быть не может: урон считает сервер), а **легальная** верхняя точка формулы копья. Модуль
нужен для того, чтобы попадать в эту точку стабильно: нужная дистанция разгона, ровный
взгляд, жаб-рывок и отпускание заряда ровно в живой стадии.

### Что реализовано

`module/combat/SpearDashModule.java`, категория Combat, машина состояний
`WAIT → AIM → JAB → CHARGE → COOLDOWN` (по образцу `AutoMaceModule`).

- `WAIT` — копьё в руке (иначе выбор лучшего копья в хотбаре: макс. `множитель + 0.1 ×
  уровень Рывка`), проверка еды/воды/элитры/езды, готовности индикатора атаки (≥ 0.93),
  поиск ближайшего игрока (`AntiBotModule` и `FriendManager` отсечены), требование
  дистанции: не больше «Стартовой дистанции» и не меньше нужного разгона;
- `AIM` — прицел с упреждением (`Упреждение` × тики до контакта), наклон взгляда
  зажимается настройкой `Макс. наклон взгляда`, чтобы «Рывок» не терял длину;
  `RotationManager.update(..., ROTATION_PRIORITY = 8)`;
- прыжок перед рывком через `LivingEntityGetNoJumpDelayAccessor.skycore$setNoJumpDelay(0)`
  + `jumpFromGround()` (воздушный рывок длиннее);
- `JAB` — `AttackHelper.sendFixedAttack`; заряд начинается **на следующем тике**,
  потому что атака в ваниле снимает использование предмета;
- `CHARGE` — удержание через `options.keyUse.setDown(true)` (как у живого игрока:
  анимация, позы копья и пакеты ванильные), страховка `gameMode.useItem` если за тик
  `isUsingItem()` так и не стало `true`; держит до `Авто-задержка заряда` (по тиру
  предмета), затем отпускает при попадании (`target.hurtTime > 0`), при входе в мёртвую
  зону (< 2.05) или по таймауту;
- `Показывать урон` — оценка `floor(множитель × скорость) + атрибутивный урон предмета`
  в чат: это именно оценка, на урон она не влияет.

Тир копья и задержка заряда определяются по строке id (`ChargedHelper.id`), наличие
копья — по `ChargedHelper.kind(stack) == "spear"`, базовый урон — по
`ChargedHelper.damage(stack)` (сумма модификаторов `ATTACK_DAMAGE`, Sharpness уже внутри).
`Items.*_SPEAR`, `SpearItem`, `Enchantments.LUNGE` и `ResourceKey.create` не
используются нигде — чтобы не зависеть от непроверенных имён 26.2.

Настройки: `Режим` (Рывок + заряд / Только рывок / Только заряд), `Радиус поиска`,
`Стартовая дистанция`, `Радиус удара`, `Макс. наклон взгляда`, `Упреждение`,
`Мин. скорость удара`, `Авто-задержка заряда`, `Задержка заряда`, `Держать заряд`,
`Прыжок перед рывком`, `Держать спринт`, `Свап на копьё`, `Требовать Рывок`,
`Контроль еды`, `Показывать урон`.

### Проверки по этой задаче

| Проверка | Результат |
|---|---|
| Синтаксис (`tree-sitter-java`) `SpearDashModule.java` и `ModuleManager.java` | 0 ошибок |
| Каждый вызов MC 26.2, который использует модуль, встречается в остальном коде SkyCore (`getMainHandItem`, `getAttackStrengthScale`, `getFoodData`, `isUsingItem`, `releaseUsingItem`, `useItem(Player, InteractionHand)`, `options.keyUse/keyJump`, `hurtTime`, `getEnchantments().entrySet()`, `selectHotbarSlot`, `players()`, `getStrictDistance`, `RotationManager.update/stopRotation`) | да |
| Имена, которые **не** проверялись и потому не использованы | `Items.*_SPEAR`, `SpearItem`, `ItemUseAnimation.SPEAR`, `Enchantments.LUNGE`, `DataComponents.KINETIC_WEAPON` |
| Уникальность имени модуля (`register` падает на дубликатах) | `Spear Dash` — единственный |
| Проверка YouGame (по требованию) | найдено: «Часть функционала **Spear Target fabric 1.21.11**» и «HitIndicator base javelin mendix 1.21.4 fabric» в разделе «Исходники читов Minecraft» ([forum 853](https://yougame.biz/forums/853/page-103), 1 Мар 2026). Открыть тему нельзя: поиск и вложения отдают страницу логина. Скачанного/заимствованного кода оттуда нет |
| Компиляция `./gradlew build` | **не выполнялась**: в этой среде нет JDK (`java: command not found`) |
| Запуск в игре / совпадение формулы с сервером | не проверялось |

### Что надо проверить первым делом в игре

1. `Spear Dash` с незеритовым копьем «Рывок III» на поляне: на 12–18 блоках до цели
   модуль должен сделать джаб, сразу начать заряд и попасть на пике скорости
   (`Показывать урон` → ~33 на голых цифрах, у цели без брони — смерть с одного удара);
2. если заряд не начинается вообще — значит в 26.2 `options.keyUse` не доходит до
   `startUseItem` в этот тик: тогда выручает страховка `gameMode.useItem`, проверь, что
   она срабатывает (иначе пришли лог);
3. если урон стабильно меньше прогноза — снизь `Задержка заряда` до фактической для
   твоего тира (незерит 9 тиков по вики) и подними `Стартовая дистанция`;
4. `Только рывок` — режим «улететь»: джаб с рывком без заряда, урона почти не даёт.

### Честно про «урон больше обычного»

Формулу сервера клиент не меняет: нет ни одного пакета, где игрок объявляет урон.
Всё, что доступно, — это входные данные формулы (скорость сближения), точность,
тайминг и количество легальных ударов. Отдельно проверенные в этом репозитории приёмы
усиления — `CriticalsModule` (крит = +50% через перестановку пакетов движения) и
`HclipCommand`/`VclipCommand` (сырые `ServerboundMovePlayerPacket.Pos`); в `Spear Dash`
они сознательно не используются: они дают флаги `Invalid Move`/`Velocity` на Grim, а
потолок копья по скорости (33 с «Рывка III», ≈ 41 с элитры и фейерверка) достигается
без них.

## 9. Spear Exploit — фриз в воздухе + банк скорости (2026-10-29)

Вопрос пользователя: можно ли «дешить» игрока, зависнуть в воздухе с зажатым дэшем,
накопить скорость и отпустить её в один удар. Ответ: да, но это уже не игровая механика
копья, а обман сервера о том, где мы находимся. Реализовано как отдельный модуль,
`Spear Dash` остался «чистым».

### Механика

| Этап | Что делает модуль | Что видит сервер |
|---|---|---|
| `AIM` | наводка на цель, наклон зажат настройкой | обычные повороты головы |
| `JUMP` | прыжок, ожидание вершины (`getDeltaMovement().y <= APEX_FALL`) | обычный прыжок |
| `FREEZE` | `anchor = позиция`, `setDeltaMovement(0)`, `fallDistance = 0` | игрок стоит в воздухе |
| `BANK` | каждый тик: `bankSpeed += импульс`, `setPos(anchor)`; `ServerboundMovePlayerPacket` отменяется, вместо него `PosRot(anchor, yaw, pitch)` через `ConsumeSilentHelper.sendSilentPacket`; ПКМ зажато (`gameMode.useItem` + `options.keyUse`), заряд уже в живой стадии | «лаг»: позиция не меняется, углы живут; у цели ощущение пропавшего интернета |
| `FLIGHT` | якорь снимается, `setDeltaMovement(dir × bankSpeed, 0.08, …)`, летим в цель с живым зарядом | дельта позиции в один тик = накопленная скорость; урон считает сам по формуле `floor(множитель × скорость)` + атрибуты |

Ванильный предел — ~10 блоков на пакет движения (`moved too quickly!` + сетбэк), поэтому
`Лимит скорости` по умолчанию 3.0 бл/тик (60 бл/с → незерит `floor(1.2 × 60) + 5 = 77`,
ваншот даже незерита с Protection IV и тотемом), а максимум настройки — 9.5.

Чем это отличается от `Air Stuck`: `AirStuckModule` каждый тик вызывает
`setDeltaMovement(Vec3.ZERO)` — то есть стирает ровно тот банк, ради которого всё
делается. Поэтому якорь реализован отдельно (механизм отмены пакетов и keep-alive —
адаптация `AirStuckModule`), а если `Air Stuck` включён, `Spear Exploit` не стартует и
пишет об этом в чат.

### Файлы

```
[+] src/main/java/net/skycore/client/combat/SpearHelper.java
[+] src/main/java/net/skycore/client/module/combat/SpearExploitModule.java
[~] src/main/java/net/skycore/client/module/combat/SpearDashModule.java
[~] src/main/java/net/skycore/client/module/ModuleManager.java
```

`SpearHelper` — новая общая расчётная часть: `isSpear`, `path`, `multiplier`,
`chargeDelayTicks`, `lungeLevel`, `baseDamage`, `lungeSpeed`, `predictedDamage`,
`projectedSpeed`, `aim`, `aimDelta`, `findBestHotbarSlot`, `findTarget`,
`isValidTarget`. `Spear Dash` переведён на него: его собственные копии `isSpear`,
`tierMultiplier`, `tierChargeDelayTicks`, `enchantLevel`, `findTarget`, `isValidTarget`,
вектора взгляда и константы удалены — дублей между двумя модулями нет.

Настройки `Spear Exploit`: `Радиус поиска`, `Импульс за тик`, `Лимит скорости`,
`Макс. наклон взгляда`, `Макс. время фриза`, `Держать заряд после`, `Ждать вершину
прыжка`, `360 keep-alive`, `Свап на копьё`, `Заряд во время фриза`, `Показывать урон`.
Выключение модуля (или `Макс. время фриза`) = отпускание: `onDisable` вызывает `release()`,
и остаток полёта/сброс ПКМ досживает обработчик `PlayerTickEndEvent`, который работает
независимо от состояния включённости.

### Что проверять в игре и что важно понимать

1. включить на земле с незеритовым копьем → должен быть прыжок, фриз и сообщения про
   «копим скорость»; через `Макс. время фриза` секунд — авто-отпускание;
2. если после отпускания сервер вернул на якорь (резиновость) — снизить
   `Лимит скорости` до 1.5–2.0 бл/тик;
3. если заряд не «ожил» к моменту контакта — увеличить `Импульс за тик`/время фриза или
   поставить `Заряд во время фриза` и ждать дольше `Авто-задержки` тира;
4. любой симулирующий античит (Grim) видит это как `Velocity`/`Invalid Move`: скорость
   появилась из ниоткуда. На ваниле и Paper без AC — проходит.
